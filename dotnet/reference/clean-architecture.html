Dependency rule

"source code dependencies can only point inwards." [2] Caranya DIP: interface di Core, implementasi di Infrastructure, disambungkan di composition root (Program.cs). UI boleh mereferensikan Infrastructure hanya untuk wiring DI. [1] Nama lain: Hexagonal, Ports-and-Adapters, Onion.

Repository di atas EF Core

ProKontraKapan tidak perlu
Rekomendasi EF Core bila memakai test double: mock IProductRepository, bukan DbSet / in-memory provider [4]. Query terkumpul di satu tempat. Contoh nyata DIP. "DbContext is a combination of the Unit Of Work and Repository patterns." [3] Repository generik = boilerplate. Biaya implementasi dan perawatan "significant". [4] CRUD kecil; tim yang memilih integration test ke database nyata (Testcontainers / SQLite). Repository "isn't an essential pattern". [5]

Jebakan: repository yang mengembalikan IQueryable membocorkan abstraksi; EF Core tetap menerjemahkan query. Kembalikan hasil jadi (IReadOnlyList, IAsyncEnumerable, Product?). [6]

Jawaban 60 detik: "Repository di atas EF Core, perlu?"

Tergantung. Pro: EF Core merekomendasikannya kalau memakai test double, jadi unit test Service cukup mock IProductRepository; query terkumpul di satu tempat; contoh DIP. Kontra: DbContext sudah Unit of Work + Repository, repository generik hanya boilerplate, dan IQueryable membocorkan abstraksi. Tidak perlu untuk CRUD kecil atau tim yang memakai integration test ke database nyata. Posisi saya: repository spesifik per Entity dengan method yang mengembalikan hasil jadi. Di Node: membungkus Prisma client, yang sendiri sudah mirip repository.

Pertanyaan lanjutan yang mungkin muncul

  • "DTO di mana?" → Application Core, sebagai tipe sederhana tanpa dependency ke UI/Infrastructure. [1]
  • "Kenapa Core mudah di-unit-test?" → "Because the Application Core doesn't depend on Infrastructure". [1]
  • "Harus empat lingkaran?" → Tidak, "the circles are schematic". [2]
  • "Satu repository per tabel?" → Dalam DDD, satu per aggregate root, bukan per tabel. [5]
  • "CQRS / MediatR?" → Cukup kenal namanya; bukan syarat Clean Architecture.
