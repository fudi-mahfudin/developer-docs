Pola yang sering diminta

// top-N per grup (= ROW_NUMBER() OVER (PARTITION BY …))
products.GroupBy(p => p.CategoryId)
        .Select(g => new { g.Key, Top = g.OrderByDescending(p => p.Price).Take(3).ToList() });
// agregat per grup (= GROUP BY)
products.GroupBy(p => p.CategoryId).Select(g => new { g.Key, Total = g.Sum(p => p.Price * p.Stock) });
// duplikat (= GROUP BY … HAVING COUNT(*) > 1)
products.GroupBy(p => p.Name).Where(g => g.Count() > 1).Select(g => g.Key);
// gabung (= INNER JOIN; sisi tanpa pasangan hilang)
products.Join(categories, p => p.CategoryId, c => c.Id, (p, c) => new { p.Name, Cat = c.Name });
// termasuk grup kosong: mulai dari sisi "induk"
categories.Select(c => new { c.Name, Total = products.Where(p => p.CategoryId == c.Id).Sum(p => p.Stock) });
// "tidak punya satu pun yang …"
categories.Where(c => !products.Any(p => p.CategoryId == c.Id && p.Stock == 0));

Jebakan

  • Urutan di dalam grup: OrderByDescending dulu, baru Take. MaxBy mengembalikan satu elemen.
  • EF Core: method C# biasa hanya boleh di Select terakhir (top-level projection). Di Where/OrderBy/GroupBy → runtime exception, bukan compile error [4].
  • GroupBy di EF Core: + agregat → GROUP BY/HAVING [5]; top-N per grup → ROW_NUMBER sejak EF Core 6 [6].
  • Multiple enumeration: hasil tidak di-cache; Count() + foreach pada query = dua query. Materialisasi sekali (ToListAsync) lalu pakai list-nya [7].

Jawaban 60 detik: First vs Single

First mengambil yang pertama cocok dan melempar exception kalau tidak ada; FirstOrDefault mengembalikan default (null untuk reference type), padanan find. Single menegaskan tepat satu: exception kalau nol atau lebih dari satu; SingleOrDefault default kalau nol, tetap exception kalau lebih dari satu. Primary key → SingleOrDefault + cek null untuk 404; satu dari banyak → OrderBy + FirstOrDefault. Semuanya eksekusi langsung; di EF Core pakai versi async.
