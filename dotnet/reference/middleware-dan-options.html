Middleware pipeline dan Options Pattern

Ringkasan satu halaman. Dari Lesson 0005.

Pipeline [1]

  • Setiap middleware: memilih meneruskan ke next atau tidak, dan bisa bekerja sebelum dan sesudah next.
  • Urutan di Program.cs = urutan request; response lewat urutan terbalik (A-B-C masuk, C-B-A keluar).
  • Short-circuit: tidak memanggil next → middleware itu menjadi terminal; endpoint tidak jalan.
  • app.Use menerima next; app.Run terminal (tanpa next).
  • Padanan Express: app.use((req, res, next) => …).

Service Scoped di middleware [2]

public class AuditMiddleware(RequestDelegate next, ILogger<AuditMiddleware> log)   // Singleton saja
{
    public async Task InvokeAsync(HttpContext ctx, AppDbContext db) { … await next(ctx); }  // Scoped di sini
}

Middleware dibuat sekali seumur aplikasi → service Scoped di constructor = captive dependency (lihat Service Lifetime).

Jawaban 60–90 detik

Request lewat pipeline middleware sesuai urutan di Program.cs; tiap middleware bekerja sebelum dan sesudah next, atau short-circuit. Exception handler paling awal (kebalikan Express), lalu HTTPS, routing, CORS, authentication, authorization, endpoint. Authentication sebelum authorization karena harus tahu siapa dulu. Middleware dibuat sekali, jadi service Scoped masuk lewat InvokeAsync. Konfigurasi berlapis: appsettings → appsettings.{Env} → User Secrets → env var → command-line; secret di User Secrets (dev) atau env var/Key Vault (prod); Service membacanya lewat IOptions<T>.
