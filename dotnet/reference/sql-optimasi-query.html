  2. Jalankan dengan actual plan + SET STATISTICS IO ON.

Estimated rows jauh dari actual rows → plan dipilih untuk jumlah baris yang salah. Penyebab: statistik, local variable (pakai rata-rata density), parameter sniffing. Scan tidak selalu buruk bila sebagian besar baris diambil.

  • Aturan: jangan bungkus kolom dengan fungsi/perhitungan; pindahkan ke sisi konstanta. Berlaku juga untuk JOIN, HAVING, GROUP BY, ORDER BY.
  • Tipe parameter harus cocok dengan kolom (nvarchar vs varchar) supaya tidak ada CONVERT_IMPLICIT pada kolom. [5]
  • Tanggal: half-open >= awal AND < berikutnya, bukan BETWEEN … '…-30'. EF Core: p.CreatedAt.Year == 2025 → DATEPART pada kolom.

Parameter sniffing [3] [6]

Plan dikompilasi untuk nilai parameter pertama, disimpan, dipakai ulang. Masalah bila data tidak merata (lab: Category 1 = 90.000, Category 6 = 20). Kena: stored procedure, sp_executesql (EF Core, Dapper), prepared query.

CaraHarga
OPTION (RECOMPILE) [7]CPU kompilasi tiap eksekusi
OPTION (OPTIMIZE FOR (@p = nilai))harus tahu nilai yang khas
OPTIMIZE FOR UNKNOWN / local variableplan rata-rata, buruk untuk nilai ekstrem
Covering index (akar: hilangkan Key Lookup)biaya tulis + storage
DBCC FREEPROCCACHE (plan_handle)darurat saja; tanpa parameter membuang semua plan

SQL Server 2022 PSP optimization (compat 160, predikat equality): beberapa plan aktif per query. Untuk demo: ALTER DATABASE SCOPED CONFIGURATION SET PARAMETER_SENSITIVE_PLAN_OPTIMIZATION = OFF lalu = ON lagi; kosongkan cache database: ALTER DATABASE SCOPED CONFIGURATION CLEAR PROCEDURE_CACHE.

Pagination [8] [9]

-- OFFSET: memproses semua baris yang dilewati; random access OK
SELECT Id, Name FROM dbo.Product ORDER BY Id OFFSET 90000 ROWS FETCH NEXT 20 ROWS ONLY;

-- Keyset: seek langsung; hanya maju/mundur, tidak bisa lompat halaman
SELECT TOP (20) Id, Name FROM dbo.Product WHERE Id > @lastId ORDER BY Id;

-- Keyset dua kunci (urutan unik: Id sebagai pemecah seri, index (Price) / (Price, Id))
SELECT TOP (20) Id, Name, Price FROM dbo.Product
WHERE Price > @lastPrice OR (Price = @lastPrice AND Id > @lastId)
ORDER BY Price, Id;
  • Urutan harus unik; database tidak punya urutan default, bahkan untuk primary key.
  • OFFSET bisa melewatkan/menggandakan baris saat data berubah; keyset tidak.
  • EF Core: Skip/Take = OFFSET; Where(p => p.Id > lastId).Take(n) = keyset.

Jawaban 60–90 detik

Ambil SQL dari log EF Core atau ToQueryString, cek N+1 dan tracking. Jalankan dengan actual plan dan STATISTICS IO. Cari scan pada tabel besar, Key Lookup ribuan kali, estimated vs actual yang meleset. Perbaiki: kolom tanpa fungsi (SARGable), index composite/covering, parameter sniffing (RECOMPILE, OPTIMIZE FOR, atau index yang menghilangkan lookup), keyset pagination untuk halaman jauh.
