Anatomi resource JSON: Patient, Encounter, Observation

Membaca JSON FHIR R4 seperti membaca tipe TypeScript: id vs Identifier, Reference, CodeableConcept/Coding, terminologi, value[x], meta, contained, extension

Target lesson ini: Anda bisa menjawab "Jelaskan JSON Observation ini. Apa itu CodeableConcept, dan kenapa ada beberapa Coding?" tanpa catatan: menunjuk setiap bagian penting (status, code, subject, valueQuantity), membedakan Coding dan CodeableConcept, menjelaskan bahwa beberapa Coding adalah translasi konsep yang sama ke LOINC, SNOMED CT, atau kode lokal, serta menjelaskan beda id dan identifier dan cara resource saling merujuk.

Semua JSON di lesson ini diadaptasi (dipendekkan) dari contoh resmi spesifikasi FHIR R4 (4.0.1); tautannya ada di setiap blok. Tanpa lab: cukup baca, jawab kuis, lalu latihan lisan. Kuis di sini adalah feedback cepat; bukti penguasaan hanya dari review campuran 0006.

1. Kerangka setiap resource, dan aturan JSON-nya (±8 menit)

Hampir semua resource diturunkan dari DomainResource, yang diturunkan dari Resource. Jadi setiap Patient, Encounter, atau Observation punya bagian bersama yang sama, lalu elemen khasnya sendiri. [1] [11]

PropertyDariIsi
resourceTypeJSONnama tipe resource; di JSON jenis resource "is carried as the property resourceType" [7]
idResourcelogical id (bagian 2)
metaResourceversionId, lastUpdated, profile, … (bagian 7)
textDomainResourcenarrative XHTML untuk dibaca manusia
containedDomainResourceresource lain yang disisipkan (bagian 7)
extension, modifierExtensionDomainResourcedata tambahan di luar definisi inti (bagian 7)

Aturan JSON yang paling sering menjebak developer JavaScript [7]:

  • Tidak ada null dan tidak ada nilai kosong. "JSON objects and arrays are never empty, and properties never have null values ... Omit a property if it is empty." Di TypeScript, semua elemen opsional adalah ?:, bukan | null.
  • Elemen yang bisa berulang selalu array, walau isinya satu: "arrays are used when the item might repeat, even if it does not repeat in a specific instance". Nama array tetap tunggal (name, identifier, coding).
  • Urutan property tidak bermakna, tapi "order within an array SHALL be maintained". Parser juga tidak boleh menganggap resourceType selalu di depan.
  • Nama property case-sensitive.

Yang menentukan "selalu array" atau "objek tunggal" adalah cardinality di definisi resource: "the lower and upper bounds on how many times this element is allowed to appear". [6] Cara membacanya sebagai tipe TypeScript:

CardinalityArtiPadanan TSContoh R4
0..1opsional, paling banyak satugender?: stringPatient.gender
1..1wajib, tepat satustatus: stringObservation.status, Observation.code
0..*opsional, boleh banyakname?: HumanName[]Patient.name, Patient.identifier
1..*wajib, minimal satutype: Coding[] (non-empty)Signature.type

Kardinalitas contoh: [8] [10] [2]. Di tabel definisi juga ada flag: ?! = modifier element (mengubah makna elemen lain, mis. Patient.active, Observation.status) dan Σ = bagian dari summary. [6]

2. Patient: id vs identifier (±10 menit)

Patient adalah "Demographics and other administrative information about an individual or animal receiving care". [8] Potongan contoh resmi: [18]

{
  "resourceType": "Patient",
  "id": "example",                          // logical id: dari server, bagian URL
  "identifier": [{                          // business identifier: 0..*, selalu array
    "use": "usual",
    "type": { "coding": [{ "system": "http://terminology.hl7.org/CodeSystem/v2-0203", "code": "MR" }] },
    "system": "urn:oid:1.2.36.146.595.217.0.1",   // namespace: "siapa yang menjamin unik"
    "value": "12345",                             // nomor rekam medis (MR)
    "assigner": { "display": "Acme Healthcare" }
  }],
  "active": true,
  "name": [
    { "use": "official", "family": "Chalmers", "given": ["Peter", "James"] },
    { "use": "usual", "given": ["Jim"] }
  ],
  "gender": "male",
  "birthDate": "1974-12-25",
  "deceasedBoolean": false,                 // choice type deceased[x] (bagian 6)
  "managingOrganization": { "reference": "Organization/1" }
}

Kutipan dan aturan tabel: [1] [2]

  • Spesifikasi memberi contoh pasien yang sama di dua server, Patient/23 dan Patient/5860200e-…, dengan identifier sama: "Given that the identifier is the same, the patient resources are understood to mean that they describe the same patient." [1]
  • Identifier.value "SHALL be unique within the defined system". system adalah URI namespace; kalau tidak ada system, "no useful matching may be performed using the value". [2]
  • Logical id bersifat "opaque": jangan mem-parsing strukturnya. [1]

3. Reference, lewat Encounter (±10 menit)

Encounter adalah "An interaction between a patient and healthcare provider(s) for the purpose of providing healthcare service(s) or assessing the health status of a patient": kunjungan rawat jalan, IGD, rawat inap, kunjungan virtual. [9] Potongan contoh resmi (kunjungan kardiologi): [19] 

{
  "resourceType": "Encounter",
  "id": "f001",
  "identifier": [{ "use": "official", "system": "http://www.amc.nl/zorgportal/identifiers/visits", "value": "v1451" }],
  "status": "finished",                                   // 1..1, planned | arrived | in-progress | finished | ...
  "class": { "system": "http://terminology.hl7.org/CodeSystem/v3-ActCode",
             "code": "AMB", "display": "ambulatory" },    // R4: Coding, bukan CodeableConcept
  "type": [{ "coding": [{ "system": "http://snomed.info/sct", "code": "270427003",
                          "display": "Patient-initiated encounter" }] }],
  "subject": { "reference": "Patient/f001", "display": "P. van de Heuvel" },
  "participant": [{ "individual": { "reference": "Practitioner/f002", "display": "P. Voigt" } }],
  "length": { "value": 140, "unit": "min", "system": "http://unitsofmeasure.org", "code": "min" },
  "reasonCode": [{ "coding": [{ "system": "http://snomed.info/sct", "code": "34068001",
                                "display": "Heart valve replacement" }] }],
  "serviceProvider": { "reference": "Organization/f001", "display": "Burgers University Medical Center" }
}

Tipe Reference berisi "at least one of a reference (literal reference), an identifier (logical reference), and a display (text description of target)". [3]

BentukContohKapan
Literal, relatif"reference": "Patient/f001"paling umum; relatif terhadap service base URL (atau fullUrl di Bundle)
Literal, absolut"reference": "http://example.org/fhir/Patient/f001"resource di server lain
Versi tertentu"Observation/1x2/_history/2"audit/provenance: menunjuk versi persis, bukan yang terbaru
Internal (contained)"reference": "#p1"menunjuk resource di contained (bagian 7)
Logical"identifier": { "system": "http://hl7.org/fhir/sid/us-ssn", "value": "000111111" }hanya tahu business identifier, tidak tahu URL-nya
+ display"display": "P. van de Heuvel"teks pendek untuk UI, bukan kunci

Semua contoh tabel dari halaman References. [3]

  • Logical reference punya harga: "none of the useful mechanisms described for working with references (e.g. chaining, includes) are possible". Kalau keduanya ada, "the literal reference is preferred". [3]
  • Definisi elemen membatasi target: Observation.subject adalah Reference(Patient | Group | Device | Location), Encounter.subject adalah Reference(Patient | Group). [10] [9]
  • Padanan JS: reference ≈ foreign key (patientId) yang ditulis sebagai path REST; display ≈ kolom nama yang di-denormalisasi supaya UI tidak perlu fetch kedua. Mengambil Patient sekaligus dengan Observation-nya (_include) dibahas di lesson 0003.

4. Observation: CodeableConcept vs Coding (±12 menit)

Ini JSON yang kemungkinan besar ditunjukkan interviewer. Contoh resmi berat badan, utuh kecuali narrative: [16]

{
  "resourceType": "Observation",
  "id": "example",
  "status": "final",                                       // 1..1, modifier (?!)
  "category": [{ "coding": [{ "system": "http://terminology.hl7.org/CodeSystem/observation-category",
                              "code": "vital-signs", "display": "Vital Signs" }] }],
  "code": {                                                // 1..1 CodeableConcept: APA yang diukur
    "coding": [
      { "system": "http://loinc.org",       "code": "29463-7",  "display": "Body Weight" },
      { "system": "http://loinc.org",       "code": "3141-9",   "display": "Body weight Measured" },
      { "system": "http://snomed.info/sct", "code": "27113001", "display": "Body weight" },
      { "system": "http://acme.org/devices/clinical-codes", "code": "body-weight", "display": "Body Weight" }
    ]
  },
  "subject": { "reference": "Patient/example" },           // SIAPA
  "encounter": { "reference": "Encounter/example" },       // DALAM kunjungan mana
  "effectiveDateTime": "2016-03-28",                       // KAPAN (choice type effective[x])
  "valueQuantity": {                                       // HASIL (choice type value[x])
    "value": 185, "unit": "lbs", "system": "http://unitsofmeasure.org", "code": "[lb_av]"
  }
}

Spesifikasi punya dua tipe untuk nilai berkode: [2]

  • Coding: "a simple direct reference to a code defined by a code system": system (URI code system), version, code, display, userSelected.
  • CodeableConcept: "a text description and/or a list of Codings": coding (0..*) + text (0..1).
type Coding = { system?: string; version?: string; code?: string; display?: string; userSelected?: boolean };
type CodeableConcept = { coding?: Coding[]; text?: string };

// Cari berdasarkan system, jangan coding[0]: urutan coding tidak bermakna.
const loinc = (cc: CodeableConcept) => cc.coding?.find(c => c.system === "http://loinc.org")?.code;
// Untuk UI: text dulu, lalu display coding mana pun, lalu code.
const label = (cc: CodeableConcept) => cc.text ?? cc.coding?.find(c => c.display)?.display ?? cc.coding?.[0]?.code;

Kenapa empat Coding? [2]

  • "The concept may be coded multiple times in different code systems ... Each coding (also referred to as a 'translation') is a representation of the concept". "There is no meaning associated with the ordering of coding within a CodeableConcept."
  • "A typical use of CodeableConcept is to send the local code that the concept was coded with, and also one or more translations to publicly defined code systems such as LOINC or SNOMED CT. Sending local codes is useful and important for the purposes of debugging and integrity auditing."
  • Kenapa tidak cukup Coding? Pengalaman HL7: "in the general case, systems need to able to exchange multiple translation codes, and/or an original text." Coding dipakai langsung hanya bila daftar kodenya disepakati semua pihak.
  • text adalah teks seperti yang dimasukkan/dipilih pengguna; kalau tidak ada coding yang userSelected, "the text (if present) is the preferred source of meaning". CodeableConcept boleh berisi text saja bila tidak ada kode yang cocok.
  • Kode hanya bermakna bersama system: "coded values are always treated as a pair composed of 'system' and 'code'". [4] Kode H di sistem interpretasi berbeda artinya dengan H di sistem lain.

Jebakan versi: di R4, Encounter.class bertipe Coding 1..1, jadi JSON-nya objek { system, code, display } tanpa coding: [...] (lihat bagian 3). [9] Di R5 elemen itu menjadi CodeableConcept 0..*. [20] Bentuk JSON ditentukan oleh tipe di definisi, jadi baca definisinya, jangan menebak.

5. Terminologi: LOINC, SNOMED CT, ICD-10 (±8 menit)

Code systemsystem di FHIRUntuk apaContoh kode
LOINC (Regenstrief Institute)http://loinc.org [12] nama observasi/tes: "The Observation.code is preferably a LOINC concept code." [10] 15074-8 Glucose [Moles/volume] in Blood
SNOMED CT (SNOMED International)http://snomed.info/sct [13] terminologi klinis luas: temuan, prosedur, alasan kunjungan, nilai berkode; "For non-numeric values, the Observation.value is preferably a SNOMED CT concept code." [10] 260385009 Negative; 34068001 Heart valve replacement
ICD-10 (WHO)http://hl7.org/fhir/sid/icd-10; varian nasional mis. …/icd-10-cm [14] klasifikasi penyakit: dasar statistik morbiditas/mortalitas, dan datanya "support payment systems" [15] J21.8 (ditulis dengan titik)
UCUMhttp://unitsofmeasure.org satuan di Quantity: "If the unit can be coded in UCUM and a code is provided, it SHOULD be a UCUM code." [2] mmol/L, [lb_av], min
  • Resource mengikat elemen berkode ke ValueSet dengan binding strength: required (SHALL dari value set itu), extensible (wajib dari value set kalau ada kode yang cocok), preferred (dianjurkan), example (hanya contoh). [4] Contoh: Observation.status required; Observation.code hanya example binding ke LOINC; Condition.code example binding ke kode SNOMED CT. [10] Profile nasional (mis. SATUSEHAT, lesson 0006) biasanya memperketatnya.
  • Kode ICD ditulis dengan titik ("ICD codes SHALL be represented with the period included"), dan ICD-9 serta ICD-10 adalah code system terpisah. [14]
  • Satu kalimat untuk interview: LOINC menamai apa yang diukur, SNOMED CT menamai konsep klinisnya, ICD-10 mengelompokkan diagnosis untuk pelaporan dan klaim.

Latihan 5 — Terminologi

6. Choice type value[x] (±7 menit)

Di definisi, Observation.value[x] bertipe Quantity | CodeableConcept | string | boolean | integer | Range | Ratio | SampledData | time | dateTime | Period dan effective[x] bertipe dateTime | Period | Timing | instant. [10] Di JSON, "[x] is replaced with the title-cased name of the type that is actually used", dan "Elements that have a choice of data type cannot repeat - they must have a maximum cardinality of 1." [6] 

// Contoh resmi glukosa (f001): effective[x] = Period, value[x] = Quantity
"effectivePeriod": { "start": "2013-04-02T09:30:10+01:00" },
"valueQuantity": { "value": 6.3, "unit": "mmol/l", "system": "http://unitsofmeasure.org", "code": "mmol/L" }

// Hasil berkode: value[x] = CodeableConcept (contoh dari halaman datatypes)
"valueCodeableConcept": { "coding": [{ "system": "http://snomed.info/sct", "code": "260385009", "display": "Negative" }],
                          "text": "Negative for Chlamydia Trachomatis rRNA" }

// Patient: deceased[x] = boolean atau dateTime
"deceasedBoolean": false

Sumber contoh: [17] [2] [18]

// Padanan TS: union yang diskriminatornya NAMA property, bukan field "type".
type ObservationValue =
  | { valueQuantity: Quantity }
  | { valueCodeableConcept: CodeableConcept }
  | { valueString: string };          // ... dan seterusnya; paling banyak satu yang ada

function showValue(o: Observation): string {
  if (o.valueQuantity) return `${o.valueQuantity.value} ${o.valueQuantity.unit ?? o.valueQuantity.code ?? ""}`;
  if (o.valueCodeableConcept) return label(o.valueCodeableConcept);
  if (o.valueString !== undefined) return o.valueString;
  return o.dataAbsentReason ? label(o.dataAbsentReason) : "-";   // value bisa absen
}

Kalau nilai tidak ada, Observation memakai dataAbsentReason, dan aturannya "dataAbsentReason SHALL only be present if Observation.value[x] is not present". [10] Catatan angka: JSON.parse mengubah 2.00 menjadi 2, padahal presisi decimal FHIR penting secara klinis; dibahas di lesson 0004. [7]

7. meta, contained, extension (±12 menit)

meta: metadata teknis, diisi server

"meta": {
  "versionId": "3",                                   // berubah setiap konten berubah
  "lastUpdated": "2024-05-01T08:15:00+07:00",         // waktu server saat versi ini dibuat
  "profile": ["http://example.org/fhir/StructureDefinition/my-patient"]   // klaim conformance
}
  • versionId "Changes each time the content of the resource changes", dan pada write "the server SHALL update this item to the current value, or remove it". Jangan mengasumsikan urutan numerik: "clients cannot assume that a versionId that comes after another one either numerically or alphabetically represents a later version". Ini dasar ETag/If-Match di lesson 0003. [1]
  • lastUpdated: pada write, server "SHALL update this item to the current time on the server". [1]
  • profile: "Profiles this resource claims to conform to", "An assertion that the content conforms to a resource profile (a StructureDefinition)". Itu klaim: server "MAY elect to remove invalid claims". [1]
  • Juga ada meta.source, meta.security (label keamanan), meta.tag. Nilai meta di contoh di atas ilustrasi, bukan dari contoh resmi.

contained: resource tanpa identitas sendiri

{
  "resourceType": "Condition",
  "contained": [{ "resourceType": "Practitioner", "id": "p1",
                  "name": [{ "family": "Person", "given": ["Patricia"] }] }],
  "asserter": { "reference": "#p1" }
}

Contoh resmi: interface engine membuat Condition dari pesan HL7 v2 dan hanya tahu nama dokter, yang tidak cukup untuk membuat Practitioner yang teridentifikasi. [3]

  • "This SHOULD NOT be done when the content can be identified properly, as once the identification is lost, it is extremely difficult ... to restore it again."
  • Contained tidak bisa berisi contained lagi, tidak boleh punya meta.versionId/lastUpdated, dan harus dirujuk dari resource induknya (atau merujuk induknya). "References to contained resources are never resolved outside the container resource."
  • Padanan JS: objek yang di-embed di dokumen MongoDB tanpa _id sendiri, dibanding dokumen terpisah yang dirujuk.

Kutipan: [3] [11]

extension: data di luar definisi inti

Spesifikasi sengaja hanya memuat kebutuhan yang disepakati umum; kebutuhan lain "will be implemented as extensions". "Every element in a resource can have extension child elements", dan "Applications should not reject resources merely because they contain extensions". [5] 

// Patient contoh resmi: jam lahir ditempel ke nilai primitif birthDate lewat _birthDate
"birthDate": "1974-12-25",
"_birthDate": {
  "extension": [{
    "url": "http://hl7.org/fhir/StructureDefinition/patient-birthTime",   // WAJIB: canonical URL definisinya
    "valueDateTime": "1974-12-25T14:35:45-05:00"                         // value[x] lagi
  }]
}

Sumber: [18] [7]

  • url wajib dan "SHALL be the canonical URL of a StructureDefinition that defines the extension". Extension "SHALL have either a value (i.e. a value[x] element) or sub-extensions, but not both". [5]
  • Extension pada elemen primitif (string, tanggal, angka) ditaruh di property bernama sama berawalan garis bawah: _birthDate, karena nilai primitif JSON tidak bisa punya property. [7]
  • modifierExtension: "If it is not safe for an application processing the content of the resource to ignore the extension it SHALL be represented using a Modifier Extension". Aplikasi yang memproses elemen dengan modifierExtension wajib memilih salah satu: memahaminya, menolak resource, memakainya hanya untuk tampilan narrative, meminta manusia mengecek, atau membawa peringatan bahwa data belum dipahami penuh. [5]
  • Hubungannya dengan lesson 0001: extension didefinisikan dan dipaketkan dalam profile/Implementation Guide, dan resource mengklaim profile lewat meta.profile.

8. Baca utuh (±5 menit)

Tutup bagian di atas. Baca Observation resmi ini dan jelaskan setiap baris dengan suara keras: siapa, apa, kapan, hasil, dan apa artinya. [17]

{
  "resourceType": "Observation",
  "id": "f001",
  "identifier": [{ "use": "official", "system": "http://www.bmc.nl/zorgportal/identifiers/observations", "value": "6323" }],
  "status": "final",
  "code": { "coding": [{ "system": "http://loinc.org", "code": "15074-8", "display": "Glucose [Moles/volume] in Blood" }] },
  "subject": { "reference": "Patient/f001", "display": "P. van de Heuvel" },
  "effectivePeriod": { "start": "2013-04-02T09:30:10+01:00" },
  "issued": "2013-04-03T15:30:10+01:00",
  "performer": [{ "reference": "Practitioner/f005", "display": "A. Langeveld" }],
  "valueQuantity": { "value": 6.3, "unit": "mmol/l", "system": "http://unitsofmeasure.org", "code": "mmol/L" },
  "interpretation": [{ "coding": [{ "system": "http://terminology.hl7.org/CodeSystem/v3-ObservationInterpretation",
                                    "code": "H", "display": "High" }] }],
  "referenceRange": [{ "low":  { "value": 3.1, "unit": "mmol/l", "system": "http://unitsofmeasure.org", "code": "mmol/L" },
                       "high": { "value": 6.2, "unit": "mmol/l", "system": "http://unitsofmeasure.org", "code": "mmol/L" } }]
}
Bandingkan bacaan Anda

Observation dengan logical id f001 dan business identifier 6323 dari sistem rumah sakit. Status final. Yang diukur: glukosa darah, LOINC 15074-8 (CodeableConcept dengan satu Coding). Pasiennya Patient/f001 (literal reference relatif + display). Waktu klinisnya effectivePeriod (choice type effective[x]), dirilis (issued) sehari kemudian, oleh Practitioner/f005. Hasil valueQuantity 6.3 mmol/L (UCUM), di atas rentang rujukan 3.1–6.2, jadi interpretation = H (High). issued adalah "Date/Time this version was made available", berbeda dari effective[x] "Clinically relevant time/time-period for observation". [10]

Latihan 9 — Ucapkan dengan suara keras

Pasang timer dan jawab dengan suara keras, seolah sedang interview. Jangan buka jawaban contoh sebelum selesai.

Interviewer menunjukkan JSON Observation berat badan dari bagian 4. "Jelaskan JSON ini. Apa itu CodeableConcept, dan kenapa ada beberapa Coding?" (90 detik)
Bandingkan dengan jawaban contoh dan checklist-nya

"Ini Observation, satu pengukuran: status final, subject merujuk Patient/example dengan reference relatif, dan hasilnya di valueQuantity: 185 dengan unit UCUM. value[x] adalah choice type, jadi nama property-nya ikut tipe. Apa yang diukur ada di code, bertipe CodeableConcept: daftar Coding plus text opsional. Setiap Coding adalah pasangan system + code (+ display), dan code hanya bermakna bersama system-nya. Ada empat Coding karena konsep yang sama dikodekan di beberapa sistem: dua LOINC, satu SNOMED CT, dan satu kode lokal. Itu translasi, urutannya tidak bermakna. Kode lokal berguna untuk debugging, kode standar untuk interoperabilitas. Di kode saya, saya cari Coding dengan system yang saya butuhkan, misalnya http://loinc.org, bukan mengambil coding[0]."

Checklist: apakah Anda menyebut…

  • resource Observation: status, subject (Reference ke Patient), dan nilai di valueQuantity?
  • CodeableConcept = daftar Coding plus text; Coding = system + code (+ display)?
  • beberapa Coding = konsep sama di beberapa code system (translasi), urutan tidak bermakna?
  • LOINC untuk Observation.code dan SNOMED CT / kode lokal sebagai translasi?
  • code selalu dibaca bersama system; di kode klien cari berdasarkan system, bukan coding[0]?
  • value[x] adalah choice type: nama property ikut tipe (valueQuantity, unit UCUM)?

Lulus kalau minimal 4 dari 6.

"Apa beda id dan identifier di resource FHIR? Bagaimana Observation menunjuk ke pasiennya?" (60 detik)
Bandingkan dengan jawaban contoh dan checklist-nya

"id adalah logical id: ditetapkan server yang menyimpan resource, unik per tipe resource di server itu, tidak pernah berubah, dan membentuk URL-nya, misalnya Patient/123. Kalau resource disalin ke server lain, id-nya bisa berbeda. identifier adalah business identifier, seperti nomor rekam medis atau NIK: pasangan system (URI namespace) + value, dan bisa banyak. Dua resource dengan identifier sama dianggap entitas yang sama. Observation menunjuk pasien lewat Reference di subject: biasanya literal reference relatif Patient/123, opsional dengan display untuk UI. Kalau URL-nya tidak diketahui, bisa logical reference lewat subject.identifier, tapi chaining dan _include tidak jalan. Padanannya: id itu primary key database, identifier itu natural key, reference itu foreign key."

Checklist: apakah Anda menyebut…

  • id = logical id dari server, unik per tipe di server itu, tidak berubah?
  • id membentuk URL resource ([base]/Patient/123) dan bisa berbeda antar server?
  • identifier = business identifier (system + value), mis. nomor rekam medis/NIK, boleh banyak?
  • identifier sama = entitas dunia nyata yang sama, dipakai untuk mencocokkan antar sistem?
  • Reference relatif Patient/123 di subject, display hanya teks untuk ditampilkan?
  • logical reference lewat Reference.identifier bila URL tidak diketahui (tanpa chaining/_include)?

Lulus kalau minimal 4 dari 6.

"Rumah sakit kami butuh data yang tidak ada di resource FHIR standar. Apa yang Anda lakukan? Jelaskan juga meta.profile dan contained." (60 detik)
Bandingkan dengan jawaban contoh dan checklist-nya

"FHIR sengaja menaruh kebutuhan di luar inti ke extension: setiap elemen boleh punya extension, yang wajib punya url ke StructureDefinition yang mendefinisikannya, plus satu value[x] atau sub-extension. Aplikasi tidak boleh menolak resource hanya karena ada extension. Kalau data itu mengubah makna resource sehingga tidak aman diabaikan, wajib pakai modifierExtension. Extension biasanya didefinisikan dalam profile, dan resource bisa mengklaim mematuhi profile lewat meta.profile; meta juga berisi versionId dan lastUpdated yang diisi server. contained beda lagi: resource kecil yang disisipkan di dalam resource lain karena tidak bisa diidentifikasi sendiri, dirujuk dengan #id; jangan dipakai kalau datanya bisa punya identitas sendiri."

Checklist: apakah Anda menyebut…

  • kebutuhan di luar inti memakai extension, bukan property JSON baru?
  • extension wajib punya url (StructureDefinition) dan value[x] atau sub-extension?
  • modifierExtension untuk data yang mengubah makna dan tidak aman diabaikan?
  • meta.profile = klaim resource mematuhi profile (StructureDefinition)?
  • meta.versionId dan meta.lastUpdated diisi server dan berubah setiap konten berubah?
  • contained = resource tanpa identitas sendiri di dalam resource lain, dirujuk dengan #id?

Lulus kalau minimal 4 dari 6. Review 0006 akan menanyakan salah satunya lagi.
