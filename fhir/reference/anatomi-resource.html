Reference [3]

{ "reference": "Patient/f001", "display": "P. van de Heuvel" }          // literal relatif + teks UI
{ "reference": "http://example.org/fhir/Patient/f001" }                 // literal absolut
{ "reference": "Observation/1x2/_history/2" }                           // versi tertentu
{ "reference": "#p1" }                                                  // ke contained
{ "identifier": { "system": "http://hl7.org/fhir/sid/us-ssn", "value": "000111111" } }  // logical
  • Minimal satu dari reference, identifier, display. Literal lebih diutamakan bila keduanya ada.
  • Logical reference: tanpa chaining / _include. Target dibatasi definisi, mis. Observation.subject: Reference(Patient | Group | Device | Location).

Coding vs CodeableConcept [2] [4]

type Coding = { system?: string; version?: string; code?: string; display?: string; userSelected?: boolean };
type CodeableConcept = { coding?: Coding[]; text?: string };

"code": { "coding": [
  { "system": "http://loinc.org",       "code": "29463-7",  "display": "Body Weight" },
  { "system": "http://snomed.info/sct", "code": "27113001", "display": "Body weight" },
  { "system": "http://acme.org/devices/clinical-codes", "code": "body-weight" } ] }
  • Kode = pasangan system + code; tanpa system tidak bisa diproses aman.
  • Beberapa Coding = translasi konsep yang sama (lokal + LOINC/SNOMED CT); urutan tidak bermakna → cari berdasarkan system, bukan coding[0].
  • text = makna seperti dimasukkan pengguna; boleh text saja bila tidak ada kode.
  • Coding langsung jarang; contoh R4: Encounter.class (Coding 1..1; R5: CodeableConcept 0..* [20]).
  • Binding strength: required · extensible · preferred · example.

Choice type [x] [6]

  • value[x] → valueQuantity | valueCodeableConcept | valueString | valueBoolean | …; satu saja, maks. kardinalitas 1.
  • Lain: effective[x] (dateTime | Period | Timing | instant), Patient.deceased[x] (boolean | dateTime), Extension.value[x].
  • Nilai absen → dataAbsentReason (hanya bila value[x] tidak ada). [10]

meta · contained · extension [1] [3] [5]

  • meta.versionId: berubah setiap konten berubah, diisi server, urutan tidak dijamin numerik (dasar ETag, lesson 0003). meta.lastUpdated: waktu server. meta.profile: klaim mematuhi StructureDefinition.
  • contained: hanya untuk data yang tidak bisa diidentifikasi (mis. nama dokter dari HL7 v2); dirujuk "#p1"; tidak bersarang; tanpa versionId/lastUpdated; tak bisa di-resolve dari luar induk.
  • extension: url wajib (canonical URL StructureDefinition) + value[x] atau sub-extension. Jangan tolak resource hanya karena extension.
  • modifierExtension: bila tidak aman diabaikan; yang tak dikenal → pahami, tolak, tampilkan narrative saja, minta cek manusia, atau beri peringatan.

Jawaban 60–90 detik

Observation = satu pengukuran: status, code (apa), subject (siapa, Reference relatif Patient/…), effective[x] (kapan), value[x] (hasil, mis. valueQuantity dengan UCUM). code adalah CodeableConcept: daftar Coding (system + code + display) plus text. Beberapa Coding = konsep sama di beberapa code system (lokal, LOINC, SNOMED CT), urutan tak bermakna, jadi cari berdasarkan system. id = logical id dari server (URL); identifier = business identifier (system + value) untuk mencocokkan antar sistem.
