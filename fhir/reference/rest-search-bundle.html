Chaining vs include [2]

ContohEfek
Chaining (filter)DiagnosticReport?subject:Patient.name=peterhanya DiagnosticReport yang subject-nya Patient bernama peter
_include (tambah, maju)Observation?patient=123&_include=Observation:patient+ Patient yang dirujuk hasil
_revinclude (tambah, balik)Patient?_id=123&_revinclude=Observation:patient+ Observation yang merujuk hasil

Format: [tipe sumber]:[search param](:[tipe target]); berantai hanya dengan :iterate. Chaining terbalik: _has (dukungan terbatas).

Error + discovery [5] [6]

  • OperationOutcome.issue[]: severity (fatal/error/warning/information) · code (IssueType: invalid, required, not-found, conflict, business-rule…) · diagnostics · expression (lokasi elemen).
  • 400 = tidak bisa di-parse / validasi dasar · 422 = melanggar profil atau aturan bisnis · 409/412 = konflik versi atau kriteria conditional tidak selektif.
  • GET [base]/metadata → CapabilityStatement: fhirVersion, format, rest.security, per resource interaction + searchParam (+ updateCreate).

Jawaban 60–90 detik

"Observation milik pasien beserta Patient-nya": Observation?patient=123&code=http://loinc.org|29463-7&_include=Observation:patient, hasil Bundle searchset, bedakan lewat search.mode, paging dengan link next. Transaction vs batch: atomik vs independen, urn:uuid hanya di transaction. Lost update: ETag = versionId, kirim If-Match, tangani 412. Error selalu OperationOutcome; kemampuan server di /metadata.
