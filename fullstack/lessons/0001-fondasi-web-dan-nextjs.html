Fondasi web dan Next.js App Router

HTML, CSS, dan JavaScript yang paling sering ditanya, lalu cara Next.js App Router membagi kerja antara server dan browser, kapan data di-cache, dan kenapa halaman kita memanggil API Express alih-alih langsung ke database

Target lesson ini: Anda bisa menjawab pertanyaan fondasi front-end (semantic HTML, a11y, box model, Flexbox vs Grid, responsive, event delegation, closure, async/await) dalam 2–3 kalimat masing-masing, lalu menjelaskan Server Component vs Client Component, perilaku caching di Next.js ≥ 16, dan alasan memisahkan API Express dari aplikasi Next.js.

Contoh di seluruh track adalah aplikasi internal Inventaris aset kantor: daftar aset (laptop, printer, proyektor), kategorinya, karyawan, dan peminjaman. Lesson ini memakai halaman "Daftar aset" sebagai contoh.

1. Semantic HTML dan a11y dasar

Semantic HTML berarti memakai elemen sesuai maknanya, bukan sesuai tampilannya: <button> untuk aksi, <nav> untuk navigasi, <main> untuk isi utama, <table> untuk data tabular. Makna ini dipakai browser, mesin pencari, dan screen reader. [1] a11y (accessibility) adalah membuat halaman bisa dipakai semua orang, termasuk pengguna keyboard dan screen reader. 

<main>
  <h1>Daftar aset</h1>
  <form role="search">
    <label for="q">Cari kode atau nama</label>
    <input id="q" name="q" type="search">
    <button type="submit">Cari</button>
  </form>
  <table>
    <caption>Aset kantor</caption>
    <thead><tr><th scope="col">Kode</th><th scope="col">Nama</th></tr></thead>
  </table>
  <img src="/foto/LTP-001.jpg" alt="Laptop Dell Latitude, kode LTP-001">
</main>
  • <label for> menghubungkan teks dengan field: screen reader membacakannya dan klik pada label memfokuskan field.
  • alt pada gambar adalah teks pengganti. Gambar dekoratif diberi alt="" supaya dilewati.
  • <button> otomatis bisa difokus dan ditekan dengan Enter/Space. <div onclick> tidak.

2. Box model, Flexbox vs Grid, responsive

Setiap elemen adalah kotak: content → padding → border → margin. Secara default width hanya mengukur content, jadi padding dan border menambah lebar. Dengan box-sizing: border-box, width sudah termasuk padding dan border. [2]

FlexboxGrid
DimensiSatu dimensi: baris atau kolomDua dimensi: baris dan kolom sekaligus [3]
ContohToolbar: tombol "Tambah aset" di kanan, kolom cari di kiriLayout halaman (sidebar + header + konten), galeri kartu aset
 
* { box-sizing: border-box; }
.toolbar { display: flex; justify-content: space-between; gap: 1rem; }
.kartu-aset { display: grid; grid-template-columns: 1fr; gap: 1rem; }

/* Mobile-first: mulai satu kolom, tambah kolom saat layar lebih lebar */
@media (min-width: 768px) {
  .kartu-aset { grid-template-columns: repeat(3, 1fr); }
}

Responsive berarti layout menyesuaikan lebar layar. Alatnya: <meta name="viewport">, unit relatif, Flexbox/Grid, dan media query yang menerapkan CSS hanya bila kondisi seperti lebar viewport terpenuhi. [4]

3. JavaScript: event bubbling dan delegation, closure, async/await

Event bubbling: event yang terjadi di elemen anak juga dijalankan di elemen induknya, naik sampai document. [5] Event delegation memanfaatkannya: pasang satu listener di induk, lalu cek event.target. Cocok untuk tabel yang barisnya berubah-ubah. 

// Satu listener untuk semua tombol "Hapus", termasuk baris yang ditambah belakangan
document.querySelector('#tabel-aset').addEventListener('click', (event) => {
  const tombol = event.target.closest('button[data-hapus]');
  if (!tombol) return;
  hapusAset(tombol.dataset.hapus);
});

Closure adalah fungsi beserta referensi ke scope tempat ia dibuat. Fungsi dalam tetap bisa membaca variabel fungsi luar setelah fungsi luar selesai. [6] let/const ber-scope blok, var ber-scope fungsi. 

function buatPenghitung() {
  let jumlah = 0;              // "disimpan" oleh closure
  return () => ++jumlah;
}
const hitung = buatPenghitung();
hitung(); hitung();            // 2: jumlah tidak bisa diakses dari luar selain lewat fungsi ini

async/await adalah cara menulis kode Promise seperti kode berurutan. Jebakan fetch: Promise-nya tidak reject untuk status HTTP error seperti 404 atau 500, hanya untuk kegagalan jaringan. Cek response.ok sendiri. [7] 

async function ambilAset(id) {
  const res = await fetch(`${API_URL}/aset/${id}`);
  if (!res.ok) throw new Error(`Gagal memuat aset: ${res.status}`);
  return res.json();
}

4. Next.js App Router: Server Component vs Client Component

Di App Router (folder app/), setiap layout dan page secara default adalah Server Component: dirender di server, bisa await data langsung, dan kodenya tidak dikirim ke browser. Komponen yang butuh state, event handler, atau API browser ditandai 'use client' dan menjadi Client Component. [8]

Server ComponentClient Component ('use client')
Ambil data, akses secret (token API), kurangi JavaScript di browseruseState, onClick, localStorage, form interaktif
Halaman daftar aset (tabel)Kolom cari dengan debounce, tombol hapus dengan konfirmasi
 
// app/aset/page.jsx: Server Component (default)
import { TombolHapus } from './tombol-hapus';

export default async function HalamanAset() {
  const res = await fetch(`${process.env.API_URL}/aset`);
  const { data } = await res.json();
  return (
    <ul>
      {data.map((a) => (
        <li key={a.id}>{a.kode} · {a.nama} <TombolHapus id={a.id} /></li>
      ))}
    </ul>
  );
}

Tips interview: dorong 'use client' sejauh mungkin ke daun pohon komponen. Hanya tombolnya yang menjadi Client Component, bukan seluruh halaman.

Pages Router (folder pages/) adalah router lama: semua komponen adalah komponen client yang juga di-render di server, dan data diambil lewat getServerSideProps/getStaticProps. Masih didukung, tapi proyek baru memakai App Router.

5. Data fetching dan caching (Next.js ≥ 16)

Ada dua model, tergantung konfigurasi. Label versi penting di sini karena perilakunya berubah antar-versi:

  • Cache Components (cacheComponents: true di next.config, diperkenalkan di Next.js 16.0 dan sudah aktif di default create-next-app terbaru): hasil fungsi atau komponen hanya di-cache bila diberi directive 'use cache', sebaiknya bersama cacheLife(). Data yang harus selalu segar tidak diberi 'use cache', melainkan dibungkus <Suspense> sehingga di-stream saat request. [9]
  • Model lama (tanpa Cache Components): sejak Next.js 15, fetch tidak di-cache secara default; caching opt-in lewat { cache: 'force-cache' } atau next: { revalidate: 60 }. [10] 
import { cacheLife, cacheTag } from 'next/cache';

// Daftar kategori jarang berubah: boleh di-cache (Next.js ≥ 16, Cache Components)
export async function ambilKategori() {
  'use cache';
  cacheLife('hours');
  cacheTag('kategori');
  const res = await fetch(`${process.env.API_URL}/kategori`);
  return res.json();
}

Jawaban singkat untuk "apakah fetch di Next.js di-cache?": "Di Next.js ≥ 15 tidak, kecuali saya opt-in. Di Next.js 16 dengan Cache Components saya menandai yang boleh di-cache dengan 'use cache', dan setelah mutasi memanggil revalidatePath atau revalidateTag."

6. Server Actions vs memanggil API Express

Server Action adalah fungsi async bertanda 'use server' yang berjalan di server dan bisa dipanggil dari <form action>. Di balik layar ia memakai POST. Server Action bisa dipanggil lewat request POST langsung, bukan hanya dari UI, jadi autentikasi dan otorisasi harus dicek di dalam setiap Server Action. [11] [12]

Browser: form→ Next.js: Server Action→ Express: REST API + Zod→ Prisma→ PostgreSQL

Di track ini Server Action tidak langsung ke database, tapi meneruskan ke API Express. Pertanyaan "kenapa tidak langsung ke DB?" dijawab begini:

  • Satu pintu untuk aturan bisnis. Validasi, otorisasi, dan audit log ada di API. Klien lain (aplikasi mobile, skrip impor Excel, integrasi dengan sistem lain) memakai aturan yang sama.
  • Pemisahan deploy dan tanggung jawab. API bisa di-deploy, di-scale, dan di-test sendiri. Kredensial database hanya ada di server API.
  • Trade-off yang jujur: ada satu hop jaringan tambahan dan dua codebase. Untuk aplikasi kecil yang hanya punya satu klien, Server Action langsung ke Prisma juga sah. Sebutkan bahwa ini keputusan sadar, bukan aturan mutlak.

Latihan: tutup bagian jawaban, lalu jelaskan dengan suara keras "Server Component vs Client Component" dan "kenapa fetch tidak di-cache" masing-masing dalam 30 detik.
