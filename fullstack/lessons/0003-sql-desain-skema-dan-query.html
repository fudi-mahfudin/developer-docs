SQL: desain skema dan query

Skema inventaris aset yang dipakai di seluruh track, normalisasi 1NF–3NF, constraint, relasi 1-N dan N-N, lalu query yang paling sering diminta di interview: JOIN, GROUP BY/HAVING, subquery vs CTE, dan window function

Target lesson ini: Anda bisa menggambar skema empat tabel inventaris aset dari spreadsheet berantakan, menjelaskan alasannya dengan istilah 1NF–3NF, dan menulis di kertas query INNER/LEFT JOIN, GROUP BY + HAVING, CTE, dan top-N per kategori dengan ROW_NUMBER().

1. Dari spreadsheet ke skema: normalisasi 1NF–3NF

Tim administrasi biasanya datang dengan satu sheet Excel seperti ini:

kode_asetnama_asetkategoriniknama_karyawandivisitgl_pinjam
LTP-001Dell LatitudeLaptopK-017RinaKeuangan2026-09-01
LTP-001, PRJ-002……K-021BudiHR2026-10-03
  • 1NF: setiap sel berisi satu nilai atomik, tanpa kelompok berulang. Sel "LTP-001, PRJ-002" melanggar; pecah menjadi dua baris peminjaman.
  • 2NF: 1NF, dan setiap kolom non-key bergantung pada seluruh primary key. Bila key-nya (kode_aset, nik, tgl_pinjam), maka nama_aset hanya bergantung pada kode_aset (partial dependency). Pindahkan ke tabel aset.
  • 3NF: 2NF, dan tidak ada transitive dependency: kolom non-key tidak bergantung pada kolom non-key lain. divisi bergantung pada nik, bukan pada peminjaman. Pindahkan ke tabel karyawan.

Hasilnya empat tabel. kategori → aset adalah relasi 1-N (satu kategori punya banyak aset). aset ↔ karyawan adalah N-N (satu aset dipinjam banyak karyawan dari waktu ke waktu, satu karyawan meminjam banyak aset), dipecah lewat tabel penghubung peminjaman yang juga menyimpan atribut relasinya (tanggal pinjam dan kembali).

2. Skema inventaris aset (PostgreSQL 18)

CREATE TABLE kategori (
  id   INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  nama TEXT NOT NULL UNIQUE
);

CREATE TABLE karyawan (
  id     INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  nik    TEXT NOT NULL UNIQUE,
  nama   TEXT NOT NULL,
  divisi TEXT NOT NULL,
  role   TEXT NOT NULL DEFAULT 'STAF' CHECK (role IN ('STAF', 'ADMIN'))
);
CREATE TABLE aset (
  id           INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  kode         TEXT NOT NULL UNIQUE,                 -- LTP-001
  nama         TEXT NOT NULL,
  kategori_id  INT NOT NULL REFERENCES kategori (id),
  harga        NUMERIC(12, 2) NOT NULL CHECK (harga >= 0),
  status       TEXT NOT NULL DEFAULT 'TERSEDIA'
               CHECK (status IN ('TERSEDIA', 'DIPINJAM', 'RUSAK')),
  tanggal_beli DATE NOT NULL,
  deleted_at   TIMESTAMPTZ                           -- soft delete (lesson 0005)
);

CREATE TABLE peminjaman (
  id              INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  aset_id         INT NOT NULL REFERENCES aset (id),
  karyawan_id     INT NOT NULL REFERENCES karyawan (id),
  tanggal_pinjam  DATE NOT NULL DEFAULT CURRENT_DATE,
  tanggal_kembali DATE,                              -- NULL = masih dipinjam
  CHECK (tanggal_kembali IS NULL OR tanggal_kembali >= tanggal_pinjam)
);
ConstraintMenjamin
PRIMARY KEYIdentitas baris: unik dan tidak NULL [1]
FOREIGN KEY (REFERENCES)Nilai kolom harus ada di tabel yang dirujuk (referential integrity): tidak ada peminjaman untuk aset fiktif [1]
UNIQUETidak ada dua aset dengan kode sama, tidak ada dua karyawan dengan NIK sama
CHECKAturan per baris: harga tidak negatif, status hanya tiga nilai, tanggal kembali tidak sebelum tanggal pinjam
GENERATED ALWAYS AS IDENTITYId otomatis versi standar SQL; SERIAL adalah cara lama di PostgreSQL [2]

Constraint di database adalah pertahanan terakhir. Validasi Zod di API (lesson 0002) memberi pesan error yang ramah, constraint menjamin data tetap benar walaupun ada bug atau skrip impor yang melewati API.

3. JOIN: INNER vs LEFT

INNER JOIN hanya mengembalikan baris yang punya pasangan di kedua tabel. LEFT JOIN mengembalikan semua baris tabel kiri; kolom tabel kanan diisi NULL bila tidak ada pasangan. [3]

-- Aset beserta nama kategorinya (setiap aset pasti punya kategori)
SELECT a.kode, a.nama, k.nama AS kategori
FROM aset a
INNER JOIN kategori k ON k.id = a.kategori_id
WHERE a.deleted_at IS NULL;

-- Semua karyawan, termasuk yang belum pernah meminjam (jumlah = 0)
SELECT kr.nama, COUNT(p.id) AS jumlah_pinjam
FROM karyawan kr
LEFT JOIN peminjaman p ON p.karyawan_id = kr.id
GROUP BY kr.id, kr.nama;

Dua jebakan klasik: COUNT(p.id) menghitung 0 untuk karyawan tanpa peminjaman, sedangkan COUNT(*) menghitung 1 (baris NULL ikut terhitung). Dan filter tabel kanan di WHERE (misalnya WHERE p.tanggal_kembali IS NULL) membuang baris NULL sehingga LEFT JOIN berubah menjadi INNER JOIN; taruh filter itu di ON.

4. GROUP BY dan HAVING

WHERE menyaring baris sebelum dikelompokkan, HAVING menyaring kelompok sesudah agregasi. [4]

-- Kategori yang punya lebih dari 5 aset aktif, dengan total nilainya
SELECT k.nama, COUNT(*) AS jumlah, SUM(a.harga) AS total_nilai
FROM aset a
JOIN kategori k ON k.id = a.kategori_id
WHERE a.deleted_at IS NULL          -- saring baris
GROUP BY k.nama
HAVING COUNT(*) > 5                 -- saring kelompok
ORDER BY total_nilai DESC;

5. Subquery vs CTE

Subquery adalah query di dalam query. EXISTS/NOT EXISTS mengecek ada-tidaknya baris yang cocok. [5] CTE (Common Table Expression, WITH nama AS (...)) memberi nama pada query bantu sehingga query panjang terbaca dari atas ke bawah; WITH RECURSIVE dipakai untuk data hierarki. [6] 

-- Subquery: aset yang belum pernah dipinjam
SELECT a.kode, a.nama
FROM aset a
WHERE NOT EXISTS (SELECT 1 FROM peminjaman p WHERE p.aset_id = a.id);

-- CTE: peminjaman aktif per divisi, lalu ambil divisi di atas rata-rata
WITH aktif AS (
  SELECT kr.divisi, COUNT(*) AS jumlah
  FROM peminjaman p JOIN karyawan kr ON kr.id = p.karyawan_id
  WHERE p.tanggal_kembali IS NULL
  GROUP BY kr.divisi
)
SELECT divisi, jumlah FROM aktif
WHERE jumlah > (SELECT AVG(jumlah) FROM aktif);

Kapan CTE: bila query bantu dipakai lebih dari sekali atau query bertingkat sulit dibaca. Hasilnya biasanya sama dengan subquery; sejak PostgreSQL 12, CTE non-rekursif yang dipakai sekali di-inline oleh planner, jadi CTE bukan lagi "selalu lebih lambat". [6]

6. Window function: top-N per kategori

Window function menghitung nilai dari sekumpulan baris yang berkaitan dengan baris saat ini tanpa meleburnya menjadi satu baris seperti GROUP BY. PARTITION BY membagi baris ke dalam kelompok, ORDER BY di dalam OVER menentukan urutan di tiap kelompok. [7] 

-- 3 aset termahal di setiap kategori
SELECT kategori_id, kode, nama, harga
FROM (
  SELECT a.*,
         ROW_NUMBER() OVER (PARTITION BY kategori_id ORDER BY harga DESC) AS urutan
  FROM aset a
  WHERE a.deleted_at IS NULL
) t
WHERE urutan <= 3;

Window function tidak boleh dipakai langsung di WHERE karena dievaluasi setelahnya, jadi dibungkus subquery atau CTE. Bedanya: ROW_NUMBER() selalu 1, 2, 3; RANK() memberi nilai sama untuk harga sama lalu melompat (1, 1, 3); DENSE_RANK() tidak melompat (1, 1, 2). [8]

Pertanyaan interview

Apa beda primary key dan unique key?
Keduanya menjamin nilai unik. Primary key satu per tabel, tidak boleh NULL, dan menjadi identitas baris yang dirujuk foreign key. Unique boleh lebih dari satu per tabel dan kolomnya boleh NULL (di PostgreSQL, beberapa NULL dianggap berbeda secara default). Contoh: aset.id primary key, aset.kode unique.
Apa beda INNER JOIN dan LEFT JOIN?
INNER JOIN hanya baris yang punya pasangan di kedua sisi. LEFT JOIN semua baris kiri, sisi kanan NULL bila tidak ada pasangan. Untuk "semua karyawan termasuk yang belum pernah meminjam", pakai LEFT JOIN dan COUNT(p.id).
Apa beda WHERE dan HAVING?
WHERE menyaring baris sebelum GROUP BY dan tidak bisa memakai agregat. HAVING menyaring kelompok sesudah agregasi, misalnya HAVING COUNT(*) > 5.
Bagaimana memodelkan relasi many-to-many?
Dengan tabel penghubung berisi dua foreign key. Di skema kita, peminjaman menghubungkan aset dan karyawan sekaligus menyimpan atribut relasi (tanggal pinjam dan kembali).
Apa itu normalisasi, dan kapan denormalisasi?
Normalisasi memecah tabel supaya setiap fakta disimpan sekali (1NF atomik, 2NF tanpa partial dependency, 3NF tanpa transitive dependency), sehingga tidak ada anomali update. Denormalisasi sengaja menduplikasi data demi kecepatan baca, misalnya tabel ringkasan laporan bulanan, dan dilakukan setelah ada bukti masalah performa.
Subquery atau CTE, mana yang lebih baik?
Untuk hasil, biasanya setara. CTE lebih mudah dibaca dan bisa dirujuk beberapa kali; WITH RECURSIVE untuk hierarki. Di PostgreSQL ≥ 12 CTE sederhana di-inline, jadi pilih yang paling jelas lalu cek dengan EXPLAIN (lesson 0004).
Apa beda ROW_NUMBER, RANK, dan DENSE_RANK?
Untuk nilai yang sama: ROW_NUMBER tetap memberi nomor berbeda (1, 2, 3), RANK memberi nomor sama lalu melompat (1, 1, 3), DENSE_RANK memberi nomor sama tanpa lompatan (1, 1, 2).

Tulis query

Soal 1. Tampilkan aset yang sedang dipinjam beserta nama peminjam dan lama pinjam (hari), urut dari yang paling lama.

SELECT a.kode, a.nama AS aset, kr.nama AS peminjam, kr.divisi,
       CURRENT_DATE - p.tanggal_pinjam AS lama_hari
FROM peminjaman p
JOIN aset a      ON a.id = p.aset_id
JOIN karyawan kr ON kr.id = p.karyawan_id
WHERE p.tanggal_kembali IS NULL
ORDER BY lama_hari DESC;

Penjelasan: mulai dari peminjaman karena faktanya ada di sana, lalu INNER JOIN ke aset dan karyawan (setiap peminjaman pasti punya keduanya karena foreign key). "Sedang dipinjam" = tanggal_kembali IS NULL (bukan = NULL, yang selalu menghasilkan NULL). Di PostgreSQL, DATE - DATE menghasilkan jumlah hari berupa integer.

Soal 2. Untuk setiap karyawan, tampilkan peminjaman terakhirnya (aset dan tanggal). Karyawan yang belum pernah meminjam tidak perlu ditampilkan.

WITH berurut AS (
  SELECT p.karyawan_id, p.aset_id, p.tanggal_pinjam,
         ROW_NUMBER() OVER (PARTITION BY p.karyawan_id
                            ORDER BY p.tanggal_pinjam DESC, p.id DESC) AS rn
  FROM peminjaman p
)
SELECT kr.nama, a.kode, b.tanggal_pinjam
FROM berurut b
JOIN karyawan kr ON kr.id = b.karyawan_id
JOIN aset a      ON a.id = b.aset_id
WHERE b.rn = 1;

Penjelasan: ini pola "baris terbaru per kelompok". ROW_NUMBER() dengan PARTITION BY karyawan_id memberi nomor 1 pada peminjaman terbaru tiap karyawan; p.id DESC memecah seri bila ada dua pinjaman di tanggal yang sama. Alternatif khusus PostgreSQL: SELECT DISTINCT ON (karyawan_id) ... ORDER BY karyawan_id, tanggal_pinjam DESC.
