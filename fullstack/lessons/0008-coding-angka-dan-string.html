Coding: angka dan string

Empat soal live coding easy yang sering muncul: palindrome integer tanpa konversi ke string, reverse integer dengan overflow, anagram, dan valid parentheses. Setiap soal ditulis dalam tujuh langkah, dengan pseudocode sebagai jawaban utama

Target lesson ini: Anda bisa menyelesaikan keempat soal di papan tulis atau editor tanpa bantuan: bertanya klarifikasi dulu, menjelaskan ide dalam satu kalimat, menulis pseudocode, menerjemahkannya ke JavaScript, menyebut kompleksitas waktu dan ruang, dan menyebut edge case sebelum interviewer menanyakannya.

Cara menjawab soal coding di interview

Interviewer posisi ini jarang menuntut solusi paling cerdas. Yang dinilai adalah cara berpikir: apakah Anda memahami soal sebelum mengetik, bisa menjelaskan rencana, dan memeriksa kasus pinggir. Karena itu setiap soal di lesson ini mengikuti urutan yang sama, dan urutan itulah yang Anda ucapkan keras-keras saat interview:

Soal→ Pertanyaan klarifikasi→ Ide→ Pseudocode→ Implementasi JavaScript→ Kompleksitas→ Edge case

Pseudocode adalah jawaban utama: bila waktu habis atau bahasa yang diminta bukan JavaScript, pseudocode yang benar sudah menunjukkan solusinya. Kompleksitas ditulis dalam notasi Big-O: O(n) berarti waktu tumbuh sebanding dengan ukuran input, O(1) berarti memori tambahan tetap berapa pun ukuran input.

Dua fakta JavaScript yang dipakai di lesson ini. Pertama, semua angka bertipe number adalah floating point 64-bit, sehingga integer hanya eksak sampai Number.MAX_SAFE_INTEGER = 253 − 1. [1] Kedua, tidak ada pembagian integer: pakai Math.floor(x / 10) untuk angka positif [2] atau Math.trunc(x / 10) yang membuang pecahan ke arah nol, juga untuk angka negatif. [3]

Soal 1: Palindrome integer tanpa konversi ke string

Soal

Diberikan integer x, kembalikan true bila x dibaca sama dari depan dan dari belakang. Contoh: 121 → true, -121 → false, 10 → false. Syarat tambahan: jangan mengubah angka menjadi string.

Pertanyaan klarifikasi

  • Apakah angka negatif dianggap palindrome? (Biasanya tidak, karena -121 dibalik menjadi 121-.)
  • Berapa rentang input: integer 32-bit bertanda, atau lebih besar? Ini menentukan apakah membalik angka bisa overflow.
  • Benar-benar tidak boleh memakai string atau array digit sama sekali?

Ide

Ambil digit dari belakang dengan x % 10 dan buang digit itu dengan pembagian integer, lalu susun digit-digit itu menjadi angka terbalik. Cukup membalik separuh angka: berhenti ketika angka terbalik sudah sama atau lebih besar dari sisa angka asli. Bila jumlah digit genap, kedua separuh harus sama (1221 → 12 dan 12); bila ganjil, digit tengah dibuang dari angka terbalik (12321 → 12 dan 123, lalu 123 / 10 dibulatkan ke bawah = 12). Membalik separuh juga berarti angka terbalik tidak pernah lebih besar dari input, sehingga tidak bisa overflow.

Pseudocode

fungsi isPalindrome(x):
    jika x < 0: kembalikan false
    jika x berakhiran 0 dan x ≠ 0: kembalikan false
    rev ← 0
    selama x > rev:
        rev ← rev × 10 + (x mod 10)
        x ← x div 10
    kembalikan (x = rev) atau (x = rev div 10)

Implementasi JavaScript

function isPalindrome(x) {
  if (x < 0 || (x % 10 === 0 && x !== 0)) return false;
  let rev = 0;
  while (x > rev) {
    rev = rev * 10 + (x % 10);
    x = Math.floor(x / 10);
  }
  return x === rev || x === Math.floor(rev / 10);
}

Jejak untuk 12321: (x, rev) = (1232, 1) → (123, 12). Loop belum berhenti karena 123 > 12, jadi satu putaran lagi: (12, 123). Sekarang x = 12 ≤ rev = 123, dan x sama dengan Math.floor(123 / 10) = 12, hasilnya true.

Kompleksitas

Waktu O(log₁₀ n): setiap putaran membuang satu digit, dan hanya separuh digit yang diproses. Ruang O(1): hanya dua variabel angka.

Edge case

  • Angka negatif: langsung false, karena tanda minus hanya ada di depan.
  • Angka berakhiran 0 (mis. 10, 120): langsung false, karena angka tidak pernah diawali 0. Tanpa pengecekan ini, 10 salah dianggap palindrome: x = 1, rev = 0, lalu x = 0 dan rev = 1, dan 0 === Math.floor(1 / 10) bernilai true. Pengecualian: 0 sendiri adalah palindrome.
  • Overflow: membalik seluruh angka bisa melewati batas 32-bit (mis. 2147483647 dibalik menjadi 7463847412). Teknik membalik separuh menghindarinya karena rev tidak pernah melebihi input. Di JavaScript angka sampai 253 − 1 masih eksak [1], tapi sebutkan alasan ini karena interviewer sering bertanya "bagaimana di Java atau C?".
  • Satu digit (0–9): selalu true; loop tidak berjalan atau berjalan sekali dan cabang rev / 10 yang cocok.

Soal 2: Reverse integer dengan overflow

Soal

Diberikan integer 32-bit bertanda x, kembalikan digitnya dalam urutan terbalik. Bila hasilnya keluar dari rentang [−231, 231 − 1] (yaitu [−2147483648, 2147483647]), kembalikan 0. Contoh: 123 → 321, -123 → -321, 120 → 21, 1534236469 → 0.

Pertanyaan klarifikasi

  • Apa yang dikembalikan bila hasilnya overflow: 0, error, atau nilai terpotong?
  • Apakah lingkungannya dianggap tidak bisa menyimpan angka di atas 32-bit (jadi overflow harus dicegah sebelum terjadi), atau cukup diperiksa setelahnya?
  • Tanda minus dipertahankan, dan nol di belakang hilang (120 → 21)?

Ide

Sama dengan soal 1: ambil digit terakhir, buang dari x, tambahkan ke rev. Sebelum menghitung rev × 10 + digit, periksa apakah hasilnya akan melewati batas. Bila rev sudah lebih besar dari 2147483647 div 10 = 214748364, perkalian dengan 10 pasti overflow; bila sama dengan 214748364, digit berikutnya tidak boleh lebih dari 7. Untuk sisi negatif batasnya −214748364 dan digit −8.

Pseudocode

MAX ← 2^31 − 1;  MIN ← −2^31
fungsi reverse(x):
    rev ← 0
    selama x ≠ 0:
        d ← x mod 10            // bertanda sama dengan x
        x ← x div 10            // dibulatkan ke arah nol
        jika rev > MAX div 10 atau (rev = MAX div 10 dan d > 7): kembalikan 0
        jika rev < MIN div 10 atau (rev = MIN div 10 dan d < −8): kembalikan 0
        rev ← rev × 10 + d
    kembalikan rev

Implementasi JavaScript

const MAX = 2 ** 31 - 1, MIN = -(2 ** 31);

function reverse(x) {
  let rev = 0;
  while (x !== 0) {
    const d = x % 10;               // -123 % 10 === -3
    x = Math.trunc(x / 10);
    if (rev > Math.trunc(MAX / 10) || (rev === Math.trunc(MAX / 10) && d > 7)) return 0;
    if (rev < Math.trunc(MIN / 10) || (rev === Math.trunc(MIN / 10) && d < -8)) return 0;
    rev = rev * 10 + d;
  }
  return rev;
}

Operator % di JavaScript adalah remainder, bukan modulo matematika: hasilnya selalu bertanda sama dengan bilangan yang dibagi, jadi -123 % 10 adalah -3. [4] Dipasangkan dengan Math.trunc, angka negatif tidak perlu ditangani terpisah. Memakai Math.floor di sini salah: Math.floor(-12.3) adalah -13. [3]

Kompleksitas

Waktu O(log₁₀ n), paling banyak 10 putaran untuk integer 32-bit. Ruang O(1).

Edge case

  • Overflow: 1534236469 dibalik menjadi 9646324351 > 231 − 1, hasilnya 0. -2147483648 dibalik menjadi −8463847412, juga 0.
  • Nol di belakang: 120 → 21; nol menjadi digit depan yang hilang dengan sendirinya.
  • Angka negatif: tanda ikut terbawa lewat remainder bertanda, -123 → -321.
  • Nol: loop tidak berjalan, hasil 0.
  • Alternatif singkat di JavaScript: karena integer sampai 253 − 1 eksak, Anda bisa membalik dulu lalu memeriksa rev > MAX || rev < MIN. Sebutkan bahwa versi di atas tetap benar di bahasa yang benar-benar 32-bit.

Soal 3: Valid anagram

Soal

Diberikan dua string s dan t, kembalikan true bila t adalah anagram dari s, yaitu memakai karakter yang sama dengan jumlah yang sama. Contoh: "anagram", "nagaram" → true; "rat", "car" → false.

Pertanyaan klarifikasi

  • Apakah huruf besar dan kecil dibedakan? Spasi dan tanda baca ikut dihitung?
  • Karakternya hanya huruf kecil a–z, atau bisa Unicode apa saja (huruf beraksen, emoji)?
  • Seberapa panjang string-nya? (Menentukan apakah sorting O(n log n) sudah cukup.)

Ide

Dua cara. (a) Urutkan kedua string lalu bandingkan: mudah ditulis, O(n log n). (b) Hitung kemunculan setiap karakter di s dengan hash map, lalu kurangi untuk setiap karakter di t; bila ada hitungan yang habis sebelum waktunya, bukan anagram. Cara (b) O(n) dan menjadi jawaban utama.

Pseudocode

fungsi isAnagram(s, t):
    jika panjang(s) ≠ panjang(t): kembalikan false
    hitung ← map kosong
    untuk setiap karakter c di s: hitung[c] ← hitung[c] + 1
    untuk setiap karakter c di t:
        jika hitung[c] = 0: kembalikan false
        hitung[c] ← hitung[c] − 1
    kembalikan true

Implementasi JavaScript

function isAnagram(s, t) {
  if (s.length !== t.length) return false;
  const count = new Map();
  for (const ch of s) count.set(ch, (count.get(ch) ?? 0) + 1);
  for (const ch of t) {
    const n = count.get(ch) ?? 0;
    if (n === 0) return false;
    count.set(ch, n - 1);
  }
  return true;
}

Map menyimpan pasangan key-value dengan key bertipe apa pun [5], dan for...of pada string berjalan per code point, bukan per unit UTF-16, sehingga emoji dihitung sebagai satu karakter. [6] Karena panjang sudah sama dan setiap karakter t mengurangi hitungan yang masih positif, tidak perlu loop ketiga untuk memeriksa sisa hitungan.

Kompleksitas

Waktu O(n), dua kali lewat string. Ruang O(k) dengan k jumlah karakter berbeda; untuk huruf a–z saja itu O(1) (paling banyak 26 entri). Versi sorting: waktu O(n log n).

Edge case

  • Panjang berbeda: langsung false tanpa menghitung.
  • Dua string kosong: true.
  • Huruf sama, jumlah beda ("aab" vs "abb"): tertangkap saat hitungan b habis.
  • Huruf besar/kecil dan Unicode: normalisasi dulu bila diminta (mis. toLowerCase()). Bila memakai sorting, ingat sort() tanpa comparator membandingkan unit UTF-16. [7]

Soal 4: Valid parentheses

Soal

Diberikan string yang hanya berisi ( ) [ ] { }, kembalikan true bila setiap kurung buka ditutup oleh kurung sejenis dalam urutan yang benar. Contoh: "()[]{}" → true, "{[]}" → true, "(]" → false, "([)]" → false.

Pertanyaan klarifikasi

  • Apakah string bisa berisi karakter lain selain kurung? Bila ya, abaikan atau anggap tidak valid?
  • Apakah string kosong dianggap valid?

Ide

Kurung yang terakhir dibuka harus menjadi yang pertama ditutup: itu perilaku stack (LIFO, last in first out). Kurung buka di-push; kurung tutup harus cocok dengan hasil pop. Di akhir, stack harus kosong. Array JavaScript sudah berfungsi sebagai stack: push menambah di ujung [8] dan pop mengambil elemen terakhir, atau undefined bila array kosong. [9]

Pseudocode

fungsi isValid(s):
    pasangan ← { ")": "(", "]": "[", "}": "{" }
    stack ← kosong
    untuk setiap karakter c di s:
        jika c kurung buka: push c ke stack
        selain itu:
            jika stack kosong atau pop(stack) ≠ pasangan[c]: kembalikan false
    kembalikan stack kosong

Implementasi JavaScript

function isValid(s) {
  const pasangan = { ")": "(", "]": "[", "}": "{" };
  const stack = [];
  for (const ch of s) {
    if (ch === "(" || ch === "[" || ch === "{") stack.push(ch);
    else if (stack.pop() !== pasangan[ch]) return false;
  }
  return stack.length === 0;
}

Pengecekan "stack kosong" sudah tercakup: pop() pada array kosong mengembalikan undefined, yang tidak pernah sama dengan kurung buka.

Kompleksitas

Waktu O(n), satu kali lewat. Ruang O(n) untuk stack pada kasus terburuk (semua kurung buka).

Edge case

  • String kosong: true (stack kosong di akhir).
  • Kurung tutup di awal ("]", "}{"): pop() pada stack kosong, langsung false.
  • Kurung buka tersisa ("(()"): loop selesai tanpa error, tapi stack tidak kosong, jadi false.
  • Silang ("([)]"): ) bertemu [ di puncak stack, false. Ini alasan menghitung jumlah buka dan tutup saja tidak cukup.
  • Panjang ganjil: pasti tidak valid; bisa dicek di awal sebagai optimasi kecil.
