Coding: array dan pencarian

Empat pola array yang paling sering keluar di live coding level easy–medium: hash map (two sum), two pointers, sliding window, dan binary search. Format tujuh langkah yang sama dengan Lesson 0008

Target lesson ini: Anda bisa mengenali pola dari kalimat soal ("pasangan yang jumlahnya", "array terurut", "substring terpanjang", "cari di data terurut"), menulis pseudocode dan JavaScript-nya, menjelaskan kenapa solusi brute force O(n²) bisa diturunkan menjadi O(n) atau O(log n), dan menyebut edge case-nya sendiri.

Soal 1: Two sum (hash map)

Soal

Diberikan array integer nums dan integer target, kembalikan index dua elemen berbeda yang jumlahnya sama dengan target. Contoh: nums = [2, 7, 11, 15], target = 9 → [0, 1].

Pertanyaan klarifikasi

  • Apakah selalu ada tepat satu jawaban? Bila tidak ada, kembalikan apa: [], null, atau error?
  • Boleh memakai elemen yang sama dua kali? (Biasanya tidak; tapi dua elemen bernilai sama di index berbeda boleh.)
  • Yang diminta index atau nilainya? Apakah array terurut?

Ide

Brute force: coba semua pasangan, O(n²). Lebih baik: untuk setiap elemen, pasangan yang dibutuhkan adalah target − nums[i]. Simpan setiap nilai yang sudah dilewati di hash map (nilai → index), sehingga pertanyaan "apakah pasangannya sudah pernah muncul?" dijawab dalam waktu rata-rata konstan. Map JavaScript wajib diimplementasikan dengan hash table atau mekanisme lain yang waktu aksesnya rata-rata sublinear. [1]

Pseudocode

fungsi twoSum(nums, target):
    dilihat ← map kosong              // nilai → index
    untuk i dari 0 sampai n − 1:
        butuh ← target − nums[i]
        jika butuh ada di dilihat: kembalikan [dilihat[butuh], i]
        dilihat[nums[i]] ← i
    kembalikan []

Implementasi JavaScript

function twoSum(nums, target) {
  const seen = new Map();             // nilai -> index
  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i];
    if (seen.has(need)) return [seen.get(need), i];
    seen.set(nums[i], i);
  }
  return [];
}

Kompleksitas

Waktu O(n): satu kali lewat, setiap operasi map rata-rata O(1). Ruang O(n) untuk map. Ini pertukaran klasik: memori ditukar dengan waktu.

Edge case

  • Nilai kembar ([3, 3], target 6): benar karena pengecekan dilakukan sebelum nilai saat ini dimasukkan ke map, jadi elemen tidak berpasangan dengan dirinya sendiri.
  • Tidak ada pasangan atau array kosong / satu elemen: kembalikan [] (sesuai jawaban klarifikasi).
  • Angka negatif dan nol: tidak butuh penanganan khusus; [-1, -2, -3, -4, -5], target −8 → [2, 4].
  • Hasil penjumlahan besar: di JavaScript aman sampai 253 − 1; di bahasa 32-bit sebutkan kemungkinan overflow.

Soal 2: Two pointers pada array terurut

Soal

Diberikan array integer nums yang sudah terurut naik dan target, kembalikan index dua elemen yang jumlahnya target, dengan memori tambahan O(1). Contoh: [2, 7, 11, 15], target 9 → [0, 1].

Pertanyaan klarifikasi

  • Urutannya naik atau turun? Ada duplikat?
  • Index mulai dari 0 atau 1? (Beberapa versi soal memakai index berbasis 1.)
  • Bila ada beberapa pasangan, cukup satu?

Ide

Karena array terurut, letakkan satu pointer di ujung kiri (nilai terkecil) dan satu di ujung kanan (nilai terbesar). Bila jumlahnya terlalu kecil, satu-satunya cara memperbesarnya adalah menggeser pointer kiri ke kanan; bila terlalu besar, geser pointer kanan ke kiri. Setiap langkah membuang satu kandidat yang pasti tidak mungkin menjadi jawaban, jadi semua pasangan yang relevan tetap terperiksa tanpa hash map.

Pseudocode

fungsi pairSorted(nums, target):
    kiri ← 0;  kanan ← n − 1
    selama kiri < kanan:
        jumlah ← nums[kiri] + nums[kanan]
        jika jumlah = target: kembalikan [kiri, kanan]
        jika jumlah < target: kiri ← kiri + 1
        selain itu: kanan ← kanan − 1
    kembalikan []

Implementasi JavaScript

function pairSorted(nums, target) {
  let lo = 0, hi = nums.length - 1;
  while (lo < hi) {
    const sum = nums[lo] + nums[hi];
    if (sum === target) return [lo, hi];
    if (sum < target) lo++;
    else hi--;
  }
  return [];
}

Variasi yang sering ditanyakan dengan pola yang sama: hapus duplikat dari array terurut secara in-place dan kembalikan jumlah elemen unik. Pointer k menunjuk posisi tulis berikutnya, pointer i membaca.

function removeDuplicates(nums) {
  if (nums.length === 0) return 0;
  let k = 1;                           // nums[0..k-1] sudah unik
  for (let i = 1; i < nums.length; i++) {
    if (nums[i] !== nums[k - 1]) nums[k++] = nums[i];
  }
  return k;                            // [0,0,1,1,2] -> 3, isi awal [0,1,2]
}

Kompleksitas

Waktu O(n): setiap langkah menggeser salah satu pointer, paling banyak n − 1 langkah. Ruang O(1). Sama untuk removeDuplicates.

Edge case

  • Array kosong atau satu elemen: loop tidak berjalan, kembalikan [] (atau 0/1 untuk hapus duplikat).
  • Tidak ada pasangan: pointer bertemu, kembalikan [].
  • Nilai kembar ([3, 3], target 6): lo < hi menjamin dua index berbeda.
  • Array tidak terurut: pola ini salah. Mengurutkan dulu (O(n log n)) mengubah index asli, jadi untuk soal "kembalikan index" pada array tidak terurut pakai hash map dari Soal 1.

Soal 3: Sliding window, substring terpanjang tanpa karakter berulang

Soal

Diberikan string s, kembalikan panjang substring terpanjang yang tidak memuat karakter berulang. Contoh: "abcabcbb" → 3 ("abc"), "bbbbb" → 1, "pwwkew" → 3 ("wke").

Pertanyaan klarifikasi

  • Substring (harus bersebelahan) atau subsequence (boleh melompat)? Soal ini substring.
  • Karakter apa saja yang mungkin: huruf kecil saja, ASCII, atau Unicode? Spasi ikut dihitung?
  • Yang diminta panjangnya saja atau substring-nya juga?

Ide

Brute force memeriksa semua substring, O(n²) atau lebih. Sliding window menjaga satu jendela [kiri, i] yang selalu bebas karakter berulang. Ujung kanan maju satu karakter setiap langkah. Bila karakter baru sudah pernah muncul di dalam jendela, ujung kiri melompat ke satu posisi setelah kemunculan terakhirnya. Map menyimpan index terakhir setiap karakter, sehingga lompatan itu O(1). Panjang terbaik dicatat setiap langkah.

Pseudocode

fungsi lengthOfLongestSubstring(s):
    terakhir ← map kosong            // karakter → index terakhir
    kiri ← 0;  terbaik ← 0
    untuk i dari 0 sampai n − 1:
        c ← s[i]
        jika c ada di terakhir dan terakhir[c] ≥ kiri:
            kiri ← terakhir[c] + 1
        terakhir[c] ← i
        terbaik ← maks(terbaik, i − kiri + 1)
    kembalikan terbaik

Implementasi JavaScript

function lengthOfLongestSubstring(s) {
  const last = new Map();             // karakter -> index terakhir
  let left = 0, best = 0, i = 0;
  for (const ch of s) {
    if (last.has(ch) && last.get(ch) >= left) left = last.get(ch) + 1;
    last.set(ch, i);
    best = Math.max(best, i - left + 1);
    i++;
  }
  return best;
}

for...of pada string berjalan per code point [2], jadi i dihitung manual sebagai posisi karakter, bukan index UTF-16.

Kompleksitas

Waktu O(n): setiap karakter diproses sekali, dan kiri hanya bergerak maju. Ruang O(k) dengan k jumlah karakter berbeda (paling banyak ukuran alfabet).

Edge case

  • String kosong: 0.
  • Semua karakter sama ("bbbbb"): 1.
  • Kemunculan lama di luar jendela ("abba"): saat a kedua muncul, index terakhir a (0) sudah di kiri jendela (kiri = 2). Syarat ≥ kiri mencegah ujung kiri mundur; tanpa syarat itu jawabannya salah (3, padahal 2).
  • Spasi dan simbol: dihitung sebagai karakter biasa (" " → 1).

Soal 4: Binary search

Soal

Diberikan array integer nums yang terurut naik dan target, kembalikan index target, atau -1 bila tidak ada. Waktu harus O(log n). Contoh: [-1, 0, 3, 5, 9, 12], target 9 → 4; target 2 → -1.

Pertanyaan klarifikasi

  • Apakah ada duplikat? Bila ada, index yang mana: sembarang, pertama, atau terakhir?
  • Bila tidak ditemukan, kembalikan -1 atau posisi sisipnya?

Ide

Bandingkan target dengan elemen tengah. Karena array terurut, satu perbandingan membuang separuh ruang pencarian: bila elemen tengah lebih kecil, target hanya mungkin di kanan; bila lebih besar, hanya di kiri. Invariant: bila target ada, ia selalu berada di [lo, hi]. Loop berhenti saat rentang kosong (lo > hi).

Pseudocode

fungsi binarySearch(nums, target):
    lo ← 0;  hi ← n − 1
    selama lo ≤ hi:
        mid ← lo + (hi − lo) div 2
        jika nums[mid] = target: kembalikan mid
        jika nums[mid] < target: lo ← mid + 1
        selain itu: hi ← mid − 1
    kembalikan −1

Implementasi JavaScript

function binarySearch(nums, target) {
  let lo = 0, hi = nums.length - 1;
  while (lo <= hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
    if (nums[mid] === target) return mid;
    if (nums[mid] < target) lo = mid + 1;
    else hi = mid - 1;
  }
  return -1;
}

Untuk pencarian di aplikasi, Array.prototype.indexOf dan includes memeriksa elemen satu per satu (linear) [3]; binary search hanya berlaku bila data terurut. Di database, index B-tree (Lesson 0004) memakai gagasan yang sama.

Kompleksitas

Waktu O(log n): ruang pencarian dibagi dua setiap putaran, jadi satu juta elemen butuh sekitar 20 perbandingan. Ruang O(1) untuk versi iteratif; versi rekursif memakai O(log n) call stack.

Edge case

  • Array kosong: hi = -1, loop tidak berjalan, -1.
  • Target di ujung (index 0 atau n − 1) dan satu elemen: syarat lo ≤ hi (bukan <) memastikan elemen terakhir yang tersisa tetap diperiksa.
  • Overflow saat menghitung mid: (lo + hi) / 2 bisa overflow di bahasa dengan integer 32-bit bila array sangat besar; lo + (hi − lo) / 2 aman. Di JavaScript tidak terjadi sampai 253 − 1 [4], tapi menyebutnya menunjukkan pemahaman.
  • Loop tak berhenti: selalu geser ke mid + 1 atau mid − 1, jangan ke mid, supaya rentang selalu mengecil.
  • Duplikat: versi ini mengembalikan salah satu index. Untuk index pertama, saat ketemu simpan mid lalu lanjutkan ke kiri (hi = mid − 1).
