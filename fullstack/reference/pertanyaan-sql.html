±30 pertanyaan SQL tersering

Jawaban satu paragraf untuk dibaca ulang menjelang interview. Semua contoh memakai skema inventaris aset dari Lesson 0003 (kategori, karyawan, aset, peminjaman); index, transaksi, dan performa dibahas lengkap di Lesson 0004. Dialek utama PostgreSQL 18, dengan catatan "Beda di MySQL" bila relevan.

Cara latihan: tutup jawaban dengan kertas, jawab dengan suara keras dalam 30–45 detik, lalu bandingkan.

Desain dan dasar

1. Apa beda DDL, DML, dan TCL?
DDL (Data Definition Language) mengubah struktur: CREATE TABLE, ALTER TABLE, DROP. DML (Data Manipulation Language) mengubah atau membaca isi: SELECT, INSERT, UPDATE, DELETE. TCL mengatur transaksi: BEGIN, COMMIT, ROLLBACK. Di PostgreSQL, DDL juga bisa di dalam transaksi dan di-rollback; di MySQL sebagian besar DDL melakukan commit implisit.
2. Apa beda primary key dan unique key?
Keduanya menjamin keunikan. Primary key hanya satu per tabel, tidak boleh NULL, dan menjadi identitas yang dirujuk foreign key (aset.id). Unique boleh beberapa per tabel dan kolomnya boleh NULL (aset.kode, karyawan.nik). [1]
3. Apa itu foreign key, dan apa pilihan ON DELETE-nya?
Foreign key memastikan nilai kolom ada di tabel yang dirujuk: peminjaman.aset_id harus ada di aset.id. Saat baris induk dihapus: NO ACTION/RESTRICT (default, tolak), CASCADE (ikut hapus anak), SET NULL, atau SET DEFAULT. [1] Untuk riwayat peminjaman, CASCADE berbahaya karena menghapus jejak audit; itu salah satu alasan aset di-soft delete.
4. Jelaskan normalisasi 1NF, 2NF, 3NF.
1NF: setiap sel atomik, tanpa kelompok berulang (bukan "LTP-001, PRJ-002" dalam satu sel). 2NF: 1NF dan setiap kolom non-key bergantung pada seluruh key, bukan sebagian (nama aset tidak disimpan di tabel peminjaman). 3NF: 2NF dan tidak ada kolom non-key yang bergantung pada kolom non-key lain (divisi bergantung pada karyawan, jadi disimpan di karyawan). Tujuannya setiap fakta disimpan sekali sehingga tidak ada anomali update.
5. Kapan denormalisasi dibenarkan?
Saat ada bukti query baca terlalu lambat dan JOIN-nya mahal, misalnya laporan bulanan nilai aset per divisi. Bentuknya bisa kolom turunan, tabel ringkasan, atau materialized view. Harganya: data duplikat yang harus dijaga tetap sinkron, jadi lakukan setelah mengukur, bukan di awal.
6. Bagaimana memodelkan relasi many-to-many?
Dengan tabel penghubung yang berisi dua foreign key. Aset dan karyawan berelasi N-N lewat peminjaman (aset_id, karyawan_id, tanggal_pinjam, tanggal_kembali); tabel penghubung sekaligus menyimpan atribut relasi.
7. Kenapa WHERE tanggal_kembali = NULL tidak mengembalikan apa-apa?
NULL berarti "tidak diketahui", dan perbandingan apa pun dengan NULL menghasilkan NULL, bukan true. Pakai IS NULL / IS NOT NULL. [2] Jebakan serupa: NOT IN (subquery) yang subquery-nya memuat NULL selalu kosong; pakai NOT EXISTS.
8. CHAR, VARCHAR, atau TEXT?
Di PostgreSQL ketiganya tidak berbeda performa; CHAR(n) malah menambah spasi padding. Pilih TEXT atau VARCHAR(n) bila memang perlu batas panjang. [3] Untuk uang pakai NUMERIC(12,2), bukan FLOAT, karena float tidak presisi untuk desimal.
9. Apa beda DELETE, TRUNCATE, dan DROP?
DELETE menghapus baris (bisa dengan WHERE), baris per baris, memicu trigger. TRUNCATE mengosongkan seluruh tabel jauh lebih cepat tanpa memindai baris; di PostgreSQL ia tetap transaksional dan bisa di-rollback. [4] DROP TABLE menghapus tabel beserta strukturnya. Beda di MySQL: TRUNCATE TABLE melakukan commit implisit sehingga tidak bisa di-rollback. [5]

Menulis query

10. Apa urutan eksekusi logis sebuah SELECT?
FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT (termasuk window function) → DISTINCT → ORDER BY → LIMIT/OFFSET. [6] Karena itu alias dari SELECT tidak bisa dipakai di WHERE, tapi bisa di ORDER BY.
11. Apa beda INNER, LEFT, RIGHT, FULL, dan CROSS JOIN?
INNER: hanya baris yang berpasangan. LEFT: semua baris kiri, kanan NULL bila tak berpasangan. RIGHT: kebalikannya (biasanya ditulis ulang sebagai LEFT). FULL: semua baris kedua sisi. CROSS: semua kombinasi (perkalian Kartesius). [7] Contoh LEFT: semua karyawan beserta jumlah pinjamannya, termasuk yang nol. Beda di MySQL: FULL OUTER JOIN tidak didukung; ditiru dengan LEFT JOIN ... UNION ... RIGHT JOIN.
12. Kenapa LEFT JOIN saya berubah jadi INNER JOIN?
Karena kondisi untuk tabel kanan ditaruh di WHERE. LEFT JOIN peminjaman p ... WHERE p.tanggal_kembali IS NULL masih benar, tapi WHERE p.tanggal_pinjam >= '2026-01-01' membuang baris yang p-nya NULL. Pindahkan kondisi itu ke ON.
13. Apa beda WHERE dan HAVING?
WHERE menyaring baris sebelum dikelompokkan dan tidak bisa memakai agregat. HAVING menyaring kelompok setelah agregasi: GROUP BY kategori_id HAVING COUNT(*) > 5.
14. COUNT(*), COUNT(kolom), dan COUNT(DISTINCT kolom)?
COUNT(*) menghitung baris. COUNT(p.id) mengabaikan NULL, sehingga setelah LEFT JOIN memberi 0 untuk karyawan tanpa pinjaman. COUNT(DISTINCT p.aset_id) menghitung aset berbeda yang pernah dipinjam seseorang.
15. UNION atau UNION ALL?
UNION menghapus baris duplikat dari hasil gabungan (butuh sort/hash, lebih lambat); UNION ALL mempertahankan semuanya. [8] Pakai UNION ALL bila tahu tidak ada duplikat atau duplikat memang diinginkan.
16. IN atau EXISTS?
EXISTS mengecek apakah subquery mengembalikan minimal satu baris; IN membandingkan nilai dengan daftar hasil subquery. [9] Untuk versi negatif pakai NOT EXISTS karena aman terhadap NULL. Contoh aset yang belum pernah dipinjam: SELECT kode FROM aset a WHERE NOT EXISTS (SELECT 1 FROM peminjaman p WHERE p.aset_id = a.id).
17. Apa itu correlated subquery?
Subquery yang merujuk kolom query luar, sehingga secara logis dievaluasi per baris luar. Contoh: aset yang harganya di atas rata-rata kategorinya, WHERE a.harga > (SELECT AVG(harga) FROM aset x WHERE x.kategori_id = a.kategori_id). Planner sering mengubahnya menjadi join, tapi bila lambat, tulis ulang dengan CTE + JOIN atau window function AVG(harga) OVER (PARTITION BY kategori_id).
18. Apa itu CTE, dan kapan dipakai?
CTE (WITH nama AS (...)) memberi nama pada query bantu supaya query panjang terbaca berurutan dan bisa dirujuk lebih dari sekali. WITH RECURSIVE dipakai untuk hierarki, misalnya struktur organisasi. Di PostgreSQL CTE sederhana yang dirujuk sekali di-inline oleh planner. [10]
19. Apa beda window function dan GROUP BY?
GROUP BY melebur baris menjadi satu per kelompok. Window function menghitung atas sekumpulan baris terkait (OVER (PARTITION BY ...)) tapi tiap baris tetap muncul. [11] Contoh: setiap aset beserta total nilai kategorinya, SUM(harga) OVER (PARTITION BY kategori_id).
20. ROW_NUMBER, RANK, DENSE_RANK?
Untuk harga sama: ROW_NUMBER tetap 1, 2, 3; RANK 1, 1, 3; DENSE_RANK 1, 1, 2. [12] Top-3 aset termahal per kategori: ROW_NUMBER() OVER (PARTITION BY kategori_id ORDER BY harga DESC) di subquery, lalu WHERE urutan <= 3 di luar. Beda di MySQL: window function baru ada di MySQL ≥ 8.0. [13]
21. Bagaimana mencari harga tertinggi kedua?
SELECT DISTINCT harga FROM aset ORDER BY harga DESC LIMIT 1 OFFSET 1; atau, untuk ke-N per kelompok, DENSE_RANK() OVER (ORDER BY harga DESC) = 2. Sebutkan bahwa DISTINCT/DENSE_RANK menangani harga kembar, dan hasilnya kosong bila hanya ada satu harga.
22. Bagaimana menemukan data duplikat?
Kelompokkan berdasarkan kolom yang seharusnya unik dan saring yang muncul lebih dari sekali: SELECT nama, divisi, COUNT(*) FROM karyawan GROUP BY nama, divisi HAVING COUNT(*) > 1;. Untuk menghapus duplikat dan menyisakan satu, beri ROW_NUMBER() OVER (PARTITION BY nama, divisi ORDER BY id) lalu hapus yang nomornya > 1. Setelah bersih, cegah dengan constraint UNIQUE.
23. LIKE vs ILIKE, dan kenapa LIKE '%laptop%' lambat?
ILIKE adalah LIKE tanpa membedakan huruf besar-kecil, khusus PostgreSQL. [14] Pola yang diawali % tidak bisa memakai index B-tree, jadi database memindai seluruh tabel. Untuk pencarian teks di tabel besar pakai index trigram (GIN) atau full-text search. Beda di MySQL: tidak ada ILIKE; perbandingan string biasanya sudah case-insensitive mengikuti collation kolom.

Index, transaksi, dan performa

24. Kolom mana yang perlu diindex?
Kolom yang sering muncul di WHERE, JOIN, dan ORDER BY pada tabel besar: foreign key (peminjaman.aset_id, karena PostgreSQL tidak membuatnya otomatis), dan kolom filter halaman daftar. Untuk composite index, kolom dengan kondisi kesamaan di depan; index (kategori_id, status) paling efisien bila kategori_id ikut difilter. [15] Beda di MySQL: InnoDB otomatis membuat index untuk foreign key.
25. Kenapa index saya tidak dipakai?
Penyebab umum: fungsi pada kolom (WHERE LOWER(kode) = 'ltp-001' tidak memakai index di kode; buat index ekspresi ON aset (LOWER(kode))) [16], wildcard di awal LIKE, tipe data yang berbeda, kolom selektivitas rendah, tabel kecil, atau statistik usang. Cek dengan EXPLAIN ANALYZE.
26. Bagaimana membaca EXPLAIN?
EXPLAIN menampilkan rencana dan estimasi; EXPLAIN ANALYZE menjalankan query dan menambahkan waktu serta baris aktual. Perhatikan jenis scan (Seq Scan vs Index Scan), estimasi baris yang jauh dari aktual, dan "Rows Removed by Filter" yang besar. [17] Karena benar-benar dijalankan, bungkus EXPLAIN ANALYZE untuk UPDATE/DELETE dengan BEGIN ... ROLLBACK.
27. Jelaskan ACID dan isolation level.
Atomicity, Consistency, Isolation, Durability. Contoh: meminjamkan aset (ubah status + insert peminjaman) dalam satu transaksi. Isolation level dari lemah ke kuat: READ UNCOMMITTED, READ COMMITTED, REPEATABLE READ, SERIALIZABLE; makin kuat, makin sedikit anomali (dirty read, non-repeatable read, phantom read) tapi makin besar kemungkinan transaksi harus diulang. Default PostgreSQL READ COMMITTED [18]; beda di MySQL: default InnoDB REPEATABLE READ. [19]
28. Apa itu deadlock dan bagaimana mencegahnya?
Dua transaksi saling menunggu lock yang dipegang yang lain. PostgreSQL mendeteksinya dan membatalkan salah satu transaksi. [20] Pencegahan: kunci baris dalam urutan yang konsisten (misalnya selalu urut id), buat transaksi sependek mungkin, dan siapkan retry di aplikasi untuk transaksi yang dibatalkan.
29. Apa itu masalah N+1?
Satu query untuk daftar lalu satu query per baris: 50 peminjaman → 51 query. Terlihat dari log query atau await di dalam loop. Perbaikannya JOIN, satu query WHERE id IN (...), atau di Prisma include: { aset: true } yang memuat relasi dengan jumlah query tetap. [21]
30. OFFSET atau keyset pagination?
LIMIT 20 OFFSET 720 sederhana dan bisa lompat ke halaman tertentu, tapi baris yang dilewati tetap dihitung sehingga makin lambat di halaman jauh. [22] Keyset WHERE id > 740 ORDER BY id LIMIT 20 cepat dan stabil saat data bertambah, tapi hanya maju/mundur berurutan.
31. Bagaimana menulis upsert (insert atau update)?
PostgreSQL: INSERT INTO kategori (nama) VALUES ('Laptop') ON CONFLICT (nama) DO NOTHING; atau DO UPDATE SET ... = EXCLUDED...., butuh constraint unique pada kolom konflik. [23] Beda di MySQL: INSERT ... ON DUPLICATE KEY UPDATE .... [24]
32. Apa itu SQL injection dan cara mencegahnya?
Input pengguna disambung ke string SQL sehingga mengubah struktur query, misalnya kode ' OR '1'='1. Pencegahan utama: query berparameter (WHERE kode = $1), bukan sambungan string; ditambah validasi input dan akun database dengan hak minimum. [25] ORM seperti Prisma memakai parameter secara default.
