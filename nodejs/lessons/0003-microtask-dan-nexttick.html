process.nextTick vs microtask; latihan tebak urutan output

Dua antrean yang tidak ada di diagram fase, tapi selalu dikosongkan lebih dulu, dan soal "tebak output" yang hampir pasti muncul di interview

Target lesson ini: Anda bisa menjelaskan kapan antrean process.nextTick dan antrean microtask (Promise.then, queueMicrotask) dikosongkan, menebak urutan output potongan kode yang mencampur keduanya dengan timer, dan menjelaskan kenapa nextTick rekursif bisa membuat I/O kelaparan (starvation).

Sebelumnya, di lesson 0002: event loop berputar melewati fase timers, poll, check, dan seterusnya. Tapi process.nextTick dan Promise.then tidak punya fase sendiri.

1. Dua antrean "di sela-sela"

process.nextTick(fn) memasukkan fn ke next tick queue. Antrean ini dikosongkan seluruhnya setelah operasi JavaScript yang sedang berjalan selesai, sebelum event loop boleh lanjut. [1] Jadi nextTick berjalan di fase mana pun loop sedang berada. [2]

Microtask queue adalah antrean lain, tempat handler then, catch, dan finally milik Promise yang sudah resolve, juga callback queueMicrotask(fn). Di Node, setiap kali next tick queue habis, microtask queue langsung dikosongkan sesudahnya. [1] Istilah resminya di spesifikasi ECMAScript adalah job: reaksi Promise dijalankan nanti, saat tidak ada kode JavaScript lain yang sedang berjalan. [3]

Kode sinkron sampai habis→ Kosongkan nextTick queue→ Kosongkan microtask queue→ Callback fase berikutnya (timer, I/O, immediate)↻

Aturan praktisnya: sinkron → nextTick → microtask (Promise) → fase event loop. Ulangi langkah nextTick → microtask setiap kali satu callback selesai.

Label versi: CommonJS vs ESM (Node 24)

Urutan "nextTick sebelum Promise" berlaku di modul CommonJS (require, file .cjs, atau .js tanpa "type": "module"). Dokumentasi Node 24 mencatat pengecualian: modul ESM sendiri sudah dijalankan sebagai bagian dari microtask queue, jadi di top-level ESM callback queueMicrotask() dan Promise.then jalan sebelum process.nextTick(). [1] Semua latihan di bawah adalah CommonJS. Kalau interviewer memberi soal tanpa konteks, sebutkan asumsi ini.

2. Starvation: antrean yang tidak pernah habis

Karena next tick queue dikosongkan seluruhnya sebelum loop lanjut, callback nextTick yang memanggil process.nextTick lagi secara rekursif bisa membuat I/O "kelaparan" (starvation): loop tidak pernah sampai ke fase poll. [2] Hal yang sama terjadi pada microtask: rantai queueMicrotask atau Promise.then yang terus menjadwalkan dirinya sendiri juga tidak memberi kesempatan fase lain berjalan. 

function loop() {
  process.nextTick(loop); // antrean tidak pernah kosong
}
loop();
setTimeout(() => console.log('tidak pernah tercetak'), 0);

Kalau Anda memang ingin "jalankan nanti tapi beri giliran ke I/O", pakai setImmediate, karena callback-nya berjalan di fase check, setelah poll. Untuk kode biasa, dokumentasi Node menyarankan queueMicrotask() daripada process.nextTick(), kecuali kemampuan khusus nextTick memang dibutuhkan. [1]

Latihan 1 — Tebak urutan output: sinkron, nextTick, Promise, timer

Baca kode (CommonJS), lalu susun baris output dari atas ke bawah. Ucapkan alasan setiap baris.

console.log('A: sync');
setTimeout(() => console.log('B: timeout'), 0);
Promise.resolve().then(() => console.log('C: promise'));
process.nextTick(() => console.log('D: nextTick'));
console.log('E: sync');
  1. A: sync
  2. E: sync
  3. D: nextTick
  4. C: promise
  5. B: timeout

Kode sinkron jalan sampai habis (A, E). Lalu next tick queue dikosongkan (D), baru microtask queue (C), walaupun Promise dijadwalkan lebih dulu di kode. Timer baru jalan saat loop masuk fase timers (B). Urutan ini deterministik karena tidak ada setImmediate yang bersaing dengan timer.

Latihan 2 — Tebak urutan output: di dalam callback I/O

Kode yang sama gayanya, tapi semuanya dijadwalkan dari dalam callback fs.readFile.

const fs = require('node:fs');
fs.readFile(__filename, () => {
  setTimeout(() => console.log('timeout'), 0);
  setImmediate(() => {
    console.log('immediate');
    process.nextTick(() => console.log('nextTick dari immediate'));
  });
  Promise.resolve().then(() => console.log('promise'));
  process.nextTick(() => console.log('nextTick'));
});
  1. nextTick
  2. promise
  3. immediate
  4. nextTick dari immediate
  5. timeout

Callback readFile berjalan di fase poll. Setelah callback itu selesai: nextTick, lalu promise. Fase berikutnya check: immediate. Setelah callback immediate selesai, next tick queue dikosongkan lagi sebelum loop lanjut, jadi "nextTick dari immediate" jalan sebelum timer. Timeout baru jalan di fase timers putaran berikutnya. Di dalam callback I/O, immediate selalu mendahului timeout (lesson 0002).

Latihan 3 — Tebak urutan output: antrean yang saling menjadwalkan

process.nextTick(() => {
  console.log('tick 1');
  Promise.resolve().then(() => console.log('promise dari tick 1'));
});
Promise.resolve().then(() => {
  console.log('promise 1');
  process.nextTick(() => console.log('tick dari promise 1'));
});
process.nextTick(() => console.log('tick 2'));
  1. tick 1
  2. tick 2
  3. promise 1
  4. promise dari tick 1
  5. tick dari promise 1

Next tick queue dikosongkan dulu: tick 1, tick 2. Selama itu "promise dari tick 1" masuk ke microtask queue di belakang "promise 1" yang sudah antre sejak kode sinkron. Microtask queue lalu dikosongkan: promise 1, promise dari tick 1. Selama itu "tick dari promise 1" masuk next tick queue, dan baru jalan setelah microtask queue habis.

Latihan lisan — Jawab lisan

Pasang timer, jawab dengan suara keras, baru buka jawaban contoh. Soal ini juga ada di bank soal dan bisa ditarik review 0012.

"Apa beda process.nextTick, Promise.then, dan setTimeout(fn, 0)? Kapan masing-masing berjalan?" (90 detik)
Bandingkan dengan jawaban contoh dan checklist-nya

"Ketiganya menunda fungsi, tapi ke antrean yang berbeda. process.nextTick masuk next tick queue, yang dikosongkan seluruhnya begitu operasi JavaScript yang sedang berjalan selesai, sebelum event loop lanjut. Promise.then dan queueMicrotask masuk microtask queue, yang di Node dikosongkan tepat setelah next tick queue. setTimeout 0 adalah timer: baru jalan saat loop masuk fase timers, minimal 1 ms kemudian. Jadi di CommonJS urutannya sinkron, nextTick, Promise, lalu timer. Pengecualiannya di top-level ESM, Promise jalan sebelum nextTick karena modul ESM sendiri sudah berjalan di dalam microtask queue. Risikonya: karena antrean itu dikosongkan sampai habis, nextTick atau microtask rekursif bisa membuat I/O starvation. Untuk kode biasa queueMicrotask lebih disarankan, dan kalau mau memberi giliran ke I/O, pakai setImmediate."

Checklist: apakah Anda menyebut…

  • nextTick queue dikosongkan setelah operasi JS saat ini, sebelum loop lanjut?
  • Promise.then dan queueMicrotask masuk microtask queue, dikosongkan setelah nextTick queue?
  • setTimeout 0 berjalan di fase timers, minimal 1 ms, setelah kedua antrean?
  • urutan CommonJS: sinkron → nextTick → Promise → timer?
  • pengecualian ESM: di top-level, Promise/queueMicrotask jalan sebelum nextTick?
  • nextTick atau microtask rekursif menyebabkan starvation; setImmediate memberi giliran ke I/O?

Lulus kalau minimal 4 dari 6.
