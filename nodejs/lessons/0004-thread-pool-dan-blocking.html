Lesson 0004 · Node.js · Modul Runtime · ±20 menit

libuv thread pool dan hal yang memblokir event loop

Node ternyata punya thread lain selain thread JavaScript. Siapa yang memakainya, kapan ia penuh, dan apa yang membuat seluruh server berhenti merespons

Target lesson ini: Anda bisa menyebut API Node yang memakai thread pool libuv dan ukuran default-nya, mengenali kode yang memblokir event loop (sync API, JSON.parse besar, regex rentan), dan menunjukkan cara mengukur event loop delay di produksi.

Sebelumnya, di lesson 0001: I/O file berjalan di thread pool libuv, dan pekerjaan CPU-bound di thread utama menahan semua request. Lesson ini membahas keduanya secara rinci.

1. Thread pool: siapa yang memakainya

Node memakai API asinkron sistem operasi kalau ada. Kalau tidak ada, libuv menjalankan API sinkron di thread pool supaya dari sisi JavaScript tetap terlihat asinkron. Yang memakai thread pool [1]:

  • semua API fs, kecuali file watcher dan versi *Sync;
  • API crypto asinkron yang berat: crypto.pbkdf2(), crypto.scrypt(), crypto.randomBytes(), crypto.randomFill(), crypto.generateKeyPair();
  • dns.lookup();
  • semua API zlib, kecuali versi sinkron.

Socket dan HTTP tidak memakai thread pool; keduanya dipantau OS (lesson 0001). Jebakan klasik ada di DNS: dns.lookup(), yang dipanggil secara internal oleh berbagai API jaringan untuk me-resolve nama host (mis. socket.connect() memakainya sebagai resolver default), memanggil getaddrinfo(3) secara sinkron di thread pool. Sebaliknya dns.resolve*() selalu melakukan query lewat jaringan secara asinkron dan tidak memakai thread pool. [2]

2. Ukurannya kecil: UV_THREADPOOL_SIZE

Ukuran default thread pool adalah 4, dan bisa diubah lewat environment variable UV_THREADPOOL_SIZE sampai maksimum absolut 1024. [3] Karena ukurannya tetap, satu jenis pekerjaan yang lambat (mis. pbkdf2 untuk hashing password) membuat API lain yang tidak berhubungan (baca file, dns.lookup) ikut melambat. [1] 

const crypto = require('node:crypto');
const start = Date.now();
for (let i = 1; i <= 5; i++) {
  crypto.pbkdf2('rahasia', 'salt', 300000, 64, 'sha512', () => {
    console.log(`hash ${i}: ${Date.now() - start} ms`);
  });
}
// Dengan pool 4: hash 1–4 selesai hampir bersamaan,
// hash 5 menunggu thread kosong, jadi waktunya ±dua kali lipat.

Set nilainya sebelum proses mulai, misalnya UV_THREADPOOL_SIZE=8 node main.js. Dokumentasi Node 24 mengingatkan bahwa process.env.UV_THREADPOOL_SIZE = … dari dalam kode tidak dijamin bekerja, karena thread pool sudah dibuat saat runtime diinisialisasi, jauh sebelum kode Anda jalan. [1]

3. Hal yang memblokir event loop

Memblokir event loop berarti satu callback berjalan begitu lama sehingga tidak ada callback lain, termasuk request HTTP lain, yang bisa jalan. Penyebab yang sering muncul [4]:

PenyebabContohGantinya
Sync APIfs.readFileSync, crypto.pbkdf2Sync, zlib.inflateSync, child_process.execSync di handler requestVersi asinkron (callback atau fs/promises). Sync boleh saat startup.
JSON.parse/JSON.stringify besarO(n) terhadap ukuran input; di panduan resmi, parse string JSON 50 MB butuh ±1,3 detik [4]Batasi ukuran body, pakai stream (lesson 0008), atau pindah ke worker.
Regex rentan (ReDoS)/(\/.+)+$/: quantifier bersarang bisa butuh waktu eksponensial pada input jahat [4]Hindari quantifier bersarang dan backreference; untuk pencocokan sederhana pakai indexOf.
Hitungan CPULoop jutaan iterasi, sorting array raksasa, resize gambarPecah per potongan dengan setImmediate (lesson 0003) atau worker_threads (lesson 0010).

ReDoS (Regular expression Denial of Service) adalah serangan yang mengirim input khusus supaya regex butuh waktu sangat lama. Karena regex dijalankan di thread JavaScript, satu request jahat cukup untuk menghentikan seluruh server.

4. Mengukur event loop delay

Event loop delay adalah selisih antara kapan sebuah callback seharusnya jalan dan kapan ia benar-benar jalan. Kalau loop terblokir, angka ini naik. Node menyediakan perf_hooks.monitorEventLoopDelay() (ada sejak Node 11.10), yang membuat histogram delay dalam nanodetik, dengan sampling setiap resolution ms (default 10). [5] Opsi samplePerIteration (sampling sekali per putaran loop) baru ada sejak Node 24.19. [5] 

const { monitorEventLoopDelay } = require('node:perf_hooks');
const h = monitorEventLoopDelay({ resolution: 20 });
h.enable();
setInterval(() => {
  const p99ms = h.percentile(99) / 1e6; // nanodetik → ms
  console.log(`event loop delay p99: ${p99ms.toFixed(1)} ms`);
  h.reset();
}, 10000);

Kirim angka p99 dan max ke sistem monitoring. p99 yang naik dari beberapa ms menjadi ratusan ms adalah tanda ada callback yang memblokir. Langkah berikutnya adalah profiling CPU (lesson 0011) untuk mencari fungsi mana.

Bandingkan dengan jawaban contoh dan checklist-nya

"Kalau semua endpoint ikut lambat, curiga pertama event loop terblokir, karena JavaScript berjalan di satu thread. Penyebab umumnya: sync API di handler seperti readFileSync atau pbkdf2Sync, JSON.parse atau stringify payload yang sangat besar, regex rentan ReDoS pada input user, atau hitungan CPU berat. Kemungkinan kedua thread pool libuv penuh. Ukurannya default 4, dan dipakai fs, dns.lookup, crypto asinkron seperti pbkdf2, dan zlib. Kalau hashing password memenuhi pool, baca file dan dns.lookup ikut antre. Untuk membuktikan, saya ukur event loop delay dengan monitorEventLoopDelay dari perf_hooks dan lihat p99-nya. Kalau tinggi, profiling CPU untuk menemukan fungsinya. Perbaikannya: ganti ke API asinkron, batasi ukuran body, perbaiki regex, pindahkan hitungan ke worker thread, atau naikkan UV_THREADPOOL_SIZE lewat environment sebelum proses mulai."

Checklist: apakah Anda menyebut…

  • semua endpoint lambat menandakan event loop terblokir (satu thread JS)?
  • minimal dua penyebab blocking: sync API, JSON.parse besar, regex ReDoS, hitungan CPU?
  • thread pool libuv default 4, dipakai fs, dns.lookup, crypto, zlib?
  • pool penuh membuat API lain yang tidak berhubungan ikut antre?
  • mengukur dengan monitorEventLoopDelay (p99/max), lalu profiling CPU?
  • perbaikan: API asinkron, worker thread, atau UV_THREADPOOL_SIZE sebelum proses mulai?

Lulus kalau minimal 4 dari 6.
