package.json, semver, lockfile, dan jenis dependency

Apa yang dijanjikan ^ dan ~, kenapa lockfile di-commit, kenapa CI memakai npm ci, dan di mana sebuah dependency harus dicantumkan

"Di laptop saya jalan, di CI rusak" sering berasal dari package.json: range versi yang longgar, lockfile yang tidak di-commit, atau paket yang salah tempat. Lesson 0013 sudah membahas field "type". Lesson ini membahas field lain yang ditanyakan interviewer.

Target lesson ini: Anda bisa menjawab "Di package.json ada ^ dan ~. Apa artinya, kenapa build di CI bisa berbeda dengan laptop, dan bagaimana mencegahnya?" tanpa catatan, dalam 60 detik, dengan batas versi yang tepat, peran lockfile, dan npm ci.

1. Semver dan range ^ vs ~

Semantic Versioning memakai format MAJOR.MINOR.PATCH: naikkan MAJOR untuk perubahan API yang tidak kompatibel, MINOR untuk fitur baru yang kompatibel, PATCH untuk perbaikan bug yang kompatibel. Versi 0.y.z adalah tahap pengembangan awal; apa pun boleh berubah kapan saja. [1]

Di package.json, versi dependency biasanya ditulis sebagai range. Batas persisnya dari node-semver, library yang dipakai npm: [2]

RangeArtinyaYang boleh berubah
^1.2.3>=1.2.3 <2.0.0minor dan patch
~1.2.3>=1.2.3 <1.3.0patch saja
^0.2.3>=0.2.3 <0.3.0patch saja (elemen bukan-nol paling kiri adalah minor)
^0.0.3>=0.0.3 <0.0.4tidak ada
1.2.3persis 1.2.3tidak ada

Aturan caret: boleh berubah selama elemen bukan-nol paling kiri tidak berubah. [2] npm install <paket> menyimpan versi dengan prefix ^ secara default (config save-prefix). [3] Artinya, tanpa lockfile, "express": "^4.18.2" bisa memasang 4.18.2 hari ini dan 4.21.0 bulan depan.

2. Lockfile dan npm ci

package.json
(range)→ npm install → package-lock.json
(versi persis, di-commit)→ npm ci → node_modules identik
di CI dan server

package-lock.json dibuat otomatis dan "describes the exact tree that was generated", sehingga install berikutnya menghasilkan pohon yang identik walaupun ada update dependency di antaranya. Tujuannya: rekan tim, deployment, dan CI memasang dependency yang persis sama, jadi file ini di-commit ke repository. [4]

npm ci dibuat untuk lingkungan otomatis seperti CI. Bedanya dengan npm install: [5]

  • Proyek wajib punya package-lock.json (atau npm-shrinkwrap.json).
  • Kalau lockfile tidak cocok dengan package.json, npm ci keluar dengan error, bukan memperbarui lockfile.
  • node_modules yang sudah ada dihapus dulu.
  • Tidak pernah menulis package.json atau lockfile: install-nya "frozen".

3. dependencies, devDependencies, peerDependencies

FieldIsinyaContoh di proyek NestJS
dependenciesDibutuhkan saat aplikasi berjalan@nestjs/core, @prisma/client
devDependenciesHanya untuk test, build, dan dokumentasi; pemakai akhir tidak butuh [6]typescript, jest, @nestjs/cli
peerDependenciesPaket "host" yang harus disediakan pemakai, biasanya untuk plugin; dipasang default sejak npm v7 [6]library plugin yang mencantumkan @nestjs/common

Kenapa peer, bukan dependencies biasa? Kalau plugin mencantumkan framework di dependencies, aplikasi bisa berakhir dengan dua salinan framework: satu milik aplikasi, satu milik plugin. Dengan peer, plugin memakai salinan milik aplikasi. Untuk image produksi, devDependencies tidak dipasang dengan npm ci --omit=dev. [5]

4. Field "main" dan "exports"

Dua field ini menentukan apa yang dimuat saat orang menulis require('pkg') atau import 'pkg'. "main" hanya mendefinisikan satu entry point. "exports" bisa mendefinisikan banyak entry point, entry berbeda untuk import dan require (conditional exports), dan menutup semua path lain. Kalau keduanya ada, "exports" yang menang. [7] 

{
  "name": "pkg",
  "type": "module",
  "main": "./dist/index.cjs",
  "exports": {
    ".": {
      "import": "./dist/index.js",
      "require": "./dist/index.cjs"
    },
    "./testing": "./dist/testing.js"
  }
}

Dengan konfigurasi ini, import 'pkg/testing' jalan, tetapi require('pkg/dist/internal.js') melempar ERR_PACKAGE_PATH_NOT_EXPORTED. [7] Akibatnya, menambahkan "exports" ke paket yang sudah dipakai orang bisa menjadi breaking change, karena path yang dulu bisa diakses sekarang tertutup. [7] Key "main" di contoh di atas hanya untuk tool lama yang belum membaca "exports".

Latihan lisan — Ucapkan dengan suara keras

Pasang timer dan jawab dengan suara keras, seolah sedang interview. Jangan buka jawaban contoh sebelum selesai. Soal ini juga ada di bank soal dan bisa ditarik review 0020.

"Di package.json ada ^ dan ~. Apa artinya, kenapa build di CI bisa berbeda dengan laptop, dan bagaimana mencegahnya?" (60 detik)
Bandingkan dengan jawaban contoh dan checklist-nya

"Versi mengikuti semver MAJOR.MINOR.PATCH: major untuk breaking change, minor untuk fitur yang kompatibel, patch untuk bug fix. Caret ^1.2.3 artinya >=1.2.3 <2.0.0, jadi minor dan patch baru boleh; tilde ~1.2.3 artinya >=1.2.3 <1.3.0, hanya patch. Untuk versi 0.x caret lebih ketat: ^0.2.3 berarti <0.3.0. npm install menyimpan dengan prefix ^ secara default. Karena range, dua kali install di waktu berbeda bisa memasang versi berbeda. Itulah gunanya package-lock.json: mencatat pohon persis yang terpasang, jadi harus di-commit. Di CI saya pakai npm ci: wajib ada lockfile, gagal kalau lockfile tidak cocok dengan package.json, menghapus node_modules lama, dan tidak menulis lockfile. Dependency yang hanya untuk test dan build saya taruh di devDependencies."

Checklist: apakah Anda menyebut…

  • semver MAJOR.MINOR.PATCH dan arti masing-masing?
  • ^ mengizinkan minor dan patch (batas major berikutnya); ~ hanya patch?
  • range membuat dua install bisa memasang versi berbeda?
  • package-lock.json mencatat pohon persis dan di-commit?
  • npm ci di CI: wajib lockfile, gagal kalau tidak cocok, tidak menulis lockfile?
  • kasus 0.x atau prefix default ^ dari npm install?

Lulus jika minimal 4 dari 6.
