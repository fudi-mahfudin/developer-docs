Controller, routing, dan lifecycle hooks

Controller sebagai pintu masuk request, decorator parameter dan status code, lalu urutan hook saat aplikasi start dan berhenti

Tiga lesson sebelumnya membahas bagaimana Nest menyusun object (module, provider, scope). Lesson ini menutup modul NestJS inti dari dua sisi: controller, tempat request HTTP masuk, dan lifecycle hooks, tempat kode Anda dijalankan saat aplikasi start (mis. connect ke database) dan saat berhenti (menutup koneksi). Live coding interview Nest hampir selalu dimulai dari menulis satu controller CRUD.

Target lesson ini: Anda bisa menulis di kertas controller CRUD kecil dengan @Param, @Query, @Body, dan status code yang benar, lalu menjawab "Di hook mana Anda connect dan disconnect database?" dengan urutan lima lifecycle hook dan syarat enableShutdownHooks().

1. Controller dan decorator routing

Controller adalah class dengan @Controller('prefix'); setiap method diberi decorator HTTP (@Get, @Post, @Put, @Patch, @Delete) dengan path tambahan. "Controllers must always belong to a module": daftarkan di controllers milik module-nya. [1] Controller sebaiknya tipis: ambil input, panggil service, kembalikan hasil. Logika bisnis ada di provider. 

@Controller('users')
export class UsersController {
  constructor(private readonly users: UsersService) {}

  @Get()                                        // GET /users?role=admin
  findAll(@Query('role') role?: string) { return this.users.findAll(role); }

  @Get(':id')                                   // GET /users/42
  findOne(@Param('id', ParseIntPipe) id: number) { return this.users.findOne(id); }

  @Post()                                       // 201 secara default
  create(@Body() dto: CreateUserDto) { return this.users.create(dto); }

  @Delete(':id')
  @HttpCode(204)
  remove(@Param('id', ParseIntPipe) id: number) { return this.users.remove(id); }
}
  • @Param, @Query, @Body mengambil route param, query string, dan body. Nilai query dan param selalu datang sebagai string; anotasi tipe number saja tidak mengubahnya, jadi pakai pipe seperti ParseIntPipe (dibahas di modul berikutnya). [1]
  • DTO (Data Transfer Object, class yang mendeskripsikan bentuk body) ditulis sebagai class, bukan interface, karena interface hilang saat transpilasi dan pipe validasi butuh metadata saat runtime. [1]
  • Return value: Nest men-serialisasi nilai yang dikembalikan menjadi JSON. Handler boleh async (mengembalikan Promise) atau mengembalikan Observable RxJS. [1]

2. Status code dan @Res

"The response's status code is 200 by default, except for POST requests, which use 201." Ubah dengan @HttpCode(...) di level handler, mis. 204 untuk DELETE tanpa body. [1] Untuk error, lempar exception (mis. NotFoundException menghasilkan 404); jangan mengatur status manual.

Jebakan klasik: meng-inject response object Express dengan @Res() membuat Nest masuk mode library-specific untuk handler itu, dan Anda "become responsible for managing the response": return value tidak lagi dikirim, dan interceptor yang mengubah response tidak bekerja. Kalau hanya butuh mengatur cookie atau header, pakai @Res({ passthrough: true }). [1]

NestJS 12: route didaftarkan sesuai urutan deklarasi, jadi di Express route berparameter seperti @Get(':id') bisa "menutupi" route statis @Get('me') yang ditulis sesudahnya. Tulis route statis lebih dulu, atau aktifkan opsi routeResolutionStrategy: 'specificity' (default-nya tetap perilaku v11). [2]

3. Lifecycle hooks

Lifecycle aplikasi Nest terbagi tiga fase: initializing, running, dan terminating. Lima hook bisa diimplementasikan di module, provider, dan controller: [3]

onModuleInit→ onApplicationBootstrap→ listen · running→ onModuleDestroy→ beforeApplicationShutdown→ onApplicationShutdown
HookDipanggil saat
onModuleInit()Dependency module host-nya sudah di-resolve
onApplicationBootstrap()Semua module sudah diinisialisasi, sebelum mulai menerima koneksi
onModuleDestroy()Setelah sinyal terminasi (mis. SIGTERM) diterima
beforeApplicationShutdown()Setelah semua onModuleDestroy() selesai; koneksi belum ditutup
onApplicationShutdown()Setelah koneksi ditutup, langkah terakhir app.close()
  • Async: onModuleInit dan onApplicationBootstrap boleh async; Nest menunggu Promise-nya selesai sebelum lanjut. Ini tempat yang tepat untuk await this.$connect() di PrismaService. [3]
  • Shutdown hooks mati secara default: listener sinyal memakai resource, jadi tiga hook terakhir hanya jalan karena sinyal kalau Anda memanggil app.enableShutdownHooks() saat bootstrap. Tanpa itu, hook hanya jalan kalau app.close() dipanggil eksplisit. [3]
  • Urutan antar module (NestJS 12): hook dipanggil per level hierarki komponen [2]; module yang di-import paling dalam (dan module global) lebih dulu, root module terakhir, dan hook setiap module di-await sebelum lanjut ke module berikutnya. Shutdown hook berjalan dengan urutan terbalik. [3] Kode yang bergantung pada urutan hook perlu dicek ulang saat upgrade dari v11.
  • Ingat dari lesson 0018: hook ini tidak dipanggil untuk class request-scoped. [3]
@Injectable()
export class PrismaService extends PrismaClient implements OnModuleInit, OnModuleDestroy {
  async onModuleInit() { await this.$connect(); }
  async onModuleDestroy() { await this.$disconnect(); }
}

// main.ts
const app = await NestFactory.create(AppModule);
app.enableShutdownHooks();   // supaya SIGTERM memicu onModuleDestroy dan seterusnya
await app.listen(3000);

Latihan lisan — Ucapkan dengan suara keras

Pasang timer dan jawab dengan suara keras, seolah sedang interview. Jangan buka jawaban contoh sebelum selesai. Soal ini juga ada di bank soal dan bisa ditarik review 0029.

"Service Anda membuka koneksi database dan koneksi Redis. Di mana Anda membuka dan menutupnya, dan apa yang harus dipastikan supaya koneksi ditutup rapi saat container dihentikan?" (60 detik)
Bandingkan dengan jawaban contoh dan checklist-nya

"Saya buka di onModuleInit, async, karena Nest menunggu Promise-nya sebelum lanjut; jadi aplikasi baru menerima request setelah koneksi siap. onApplicationBootstrap juga bisa, dipanggil setelah semua module siap tapi sebelum listen. Saya tutup di onModuleDestroy, atau onApplicationShutdown untuk hal yang harus terakhir. Urutan shutdown-nya onModuleDestroy, beforeApplicationShutdown, lalu onApplicationShutdown setelah koneksi HTTP ditutup. Yang sering lupa: shutdown hook mati secara default, jadi di main.ts harus ada app.enableShutdownHooks(), kalau tidak SIGTERM dari orchestrator tidak memicu hook apa pun. Di NestJS 12 hook dipanggil per level hierarki: module terdalam lebih dulu saat init, dan terbalik saat shutdown. Dan hook ini tidak jalan untuk provider request-scoped."

Checklist: apakah Anda menyebut…

  • connect di onModuleInit (atau onApplicationBootstrap) dan bahwa hook async di-await?
  • disconnect di onModuleDestroy atau onApplicationShutdown?
  • urutan shutdown: onModuleDestroy, beforeApplicationShutdown, onApplicationShutdown?
  • enableShutdownHooks() wajib supaya SIGTERM memicu hook?
  • urutan antar module: terdalam dulu saat init, terbalik saat shutdown (NestJS 12)?
  • hook tidak dipanggil untuk class request-scoped?

Lulus jika minimal 4 dari 6.

Latihan tulis kode — di kertas, tanpa IDE

Tulis jawabannya di kertas dulu, baru buka contoh. Soal ini juga ada di bank soal dan bisa ditarik review 0029.

"Tulis ProductsController dengan prefix products: GET /products?page= (page angka, default 1), GET /products/:id, POST /products dengan body CreateProductDto, dan DELETE /products/:id yang mengembalikan 204. Semua memanggil ProductsService." (5 menit)
Bandingkan dengan jawaban contoh dan checklist-nya 
@Controller('products')
export class ProductsController {
  constructor(private readonly products: ProductsService) {}

  @Get()
  findAll(@Query('page', new DefaultValuePipe(1), ParseIntPipe) page: number) {
    return this.products.findAll(page);
  }

  @Get(':id')
  findOne(@Param('id', ParseIntPipe) id: number) { return this.products.findOne(id); }

  @Post()
  create(@Body() dto: CreateProductDto) { return this.products.create(dto); }

  @Delete(':id')
  @HttpCode(204)
  remove(@Param('id', ParseIntPipe) id: number) { return this.products.remove(id); }
}

Checklist: apakah kode Anda…

  • memakai @Controller('products') dan meng-inject service lewat constructor?
  • memakai decorator HTTP yang benar dengan path ':id'?
  • mengubah param/query ke angka dengan ParseIntPipe (bukan anotasi tipe saja)?
  • memberi default untuk page (mis. DefaultValuePipe)?
  • memakai @Body() dengan DTO berupa class?
  • memberi @HttpCode(204) di DELETE dan membiarkan POST di 201 default?

Lulus jika minimal 4 dari 6.
