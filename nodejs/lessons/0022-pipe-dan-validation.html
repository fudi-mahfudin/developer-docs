Pipe dan ValidationPipe; latihan tulis DTO

Pipe bawaan untuk parameter, ValidationPipe untuk body, dan tiga opsi yang selalu ditanyakan: whitelist, forbidNonWhitelisted, transform

Di lesson 0021, pipe adalah langkah terakhir sebelum handler. Tugasnya sempit: memastikan argumen yang diterima handler sudah dalam bentuk yang benar, atau menolak request kalau tidak. Lesson ini membahas pipe bawaan, ValidationPipe dengan DTO, lalu Anda menulis DTO sendiri di kertas.

Target lesson ini: Anda bisa menulis DTO dengan decorator class-validator dan memasang ValidationPipe global tanpa melihat dokumentasi, lalu menjelaskan apa yang dilakukan whitelist, forbidNonWhitelisted, dan transform, dan kenapa DTO harus class, bukan interface.

1. Dua tugas pipe: transformasi dan validasi

Pipe adalah class yang mengimplementasikan PipeTransform. Dokumentasi NestJS menyebut dua kegunaan: transformation (mengubah input ke bentuk yang diinginkan, mis. string ke integer) dan validation (memeriksa input; kalau valid diteruskan apa adanya, kalau tidak dilempar exception). [1] Pipe berjalan di dalam exceptions zone: exception dari pipe ditangani exception filter, dan handler tidak dipanggil sama sekali. [1]

Pipe bawaan diekspor dari @nestjs/common: ValidationPipe, ParseIntPipe, ParseFloatPipe, ParseBoolPipe, ParseArrayPipe, ParseUUIDPipe, ParseEnumPipe, DefaultValuePipe, ParseFilePipe, ParseDatePipe, dan StandardSchemaValidationPipe. [1] 

@Get(':id')
findOne(@Param('id', ParseIntPipe) id: number) {
  return this.ordersService.findOne(id);   // id dijamin number
}

@Get()
findAll(@Query('page', new DefaultValuePipe(1), ParseIntPipe) page: number) { /* ... */ }

GET /orders/abc tidak pernah sampai ke service: ParseIntPipe melempar exception dan client menerima 400 dengan pesan "Validation failed (numeric string is expected)". Kalau Anda ingin status lain, berikan instance, bukan class: new ParseIntPipe({ errorHttpStatusCode: HttpStatus.NOT_ACCEPTABLE }). [1]

2. ValidationPipe dan DTO

DTO (data transfer object) adalah class yang menggambarkan bentuk body request. ValidationPipe memakai dua paket, class-validator (decorator aturan seperti @IsEmail()) dan class-transformer (mengubah objek JSON biasa menjadi instance class DTO), yang dipasang dengan npm i class-validator class-transformer. [2] 

// create-user.dto.ts
import { IsEmail, IsString, MinLength, IsOptional, IsInt, Min } from 'class-validator';

export class CreateUserDto {
  @IsEmail()
  email: string;

  @IsString()
  @MinLength(8)
  password: string;

  @IsOptional()
  @IsInt()
  @Min(18)
  age?: number;
}

// main.ts
app.useGlobalPipes(new ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true }));

Body yang gagal menghasilkan 400 Bad Request dengan daftar pesan, mis. { "statusCode": 400, "error": "Bad Request", "message": ["email must be an email"] }. [2]

Kenapa class, bukan interface? Interface TypeScript hilang saat dikompilasi ke JavaScript. Nest membaca tipe parameter lewat metadata yang dipancarkan compiler untuk class (opsi emitDecoratorMetadata), dan TypeScript "does not emit metadata for generics or interfaces", jadi ValidationPipe tidak tahu aturan apa yang harus dicek. [2]

Tiga opsi yang selalu ditanyakan

OpsiEfekContoh: body { "email": "a@b.co", "password": "rahasia123", "isAdmin": true }
whitelist: trueProperti tanpa decorator validasi dibuang dari objekisAdmin hilang diam-diam; handler tidak melihatnya
forbidNonWhitelisted: trueBersama whitelist: properti asing ditolak, bukan dibuang400: property isAdmin should not exist
transform: trueBody diubah menjadi instance DTO; tipe primitif ikut dikonversi@Param('id') id: number benar-benar number

whitelist "will strip validated (returned) object of any properties that do not use any validation decorators", sedangkan forbidNonWhitelisted "instead of stripping non-whitelisted properties validator will throw an exception." [2] Tanpa transform, handler menerima objek JSON biasa, bukan instance DTO; dengan transform, "ValidationPipe also converts primitive types", karena path dan query parameter selalu datang sebagai string. [2] whitelist adalah pertahanan murah terhadap mass assignment: client mengirim field yang tidak seharusnya ia atur (seperti isAdmin) dan field itu ikut tersimpan.

NestJS ≥ 12: StandardSchemaValidationPipe memvalidasi dengan skema dari library yang mendukung Standard Schema (Zod, Valibot, ArkType), lewat opsi baru schema di @Body(), @Query(), dan @Param(). Ini pilihan tambahan; alur DTO + decorator class-validator tetap didukung di v12. [3]

Latihan tulis kode — DTO + validation di kertas

Tutup editor. Tulis di kertas, lalu bacakan alasannya dengan suara keras seolah sedang live coding. Batas waktu 5 menit.

"Tulis DTO CreateProductDto untuk POST /products: name string wajib maksimal 100 karakter, price angka positif, tags array string opsional. Pasang validasi supaya field asing ditolak dan id di GET /products/:id diterima sebagai number."
Bandingkan dengan jawaban contoh dan checklist-nya 
import { IsString, IsNotEmpty, MaxLength, IsNumber, IsPositive, IsOptional, IsArray } from 'class-validator';

export class CreateProductDto {
  @IsString() @IsNotEmpty() @MaxLength(100)
  name: string;

  @IsNumber() @IsPositive()
  price: number;

  @IsOptional() @IsArray() @IsString({ each: true })
  tags?: string[];
}

// main.ts
app.useGlobalPipes(new ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true }));

// products.controller.ts
@Post() create(@Body() dto: CreateProductDto) { return this.products.create(dto); }
@Get(':id') findOne(@Param('id', ParseIntPipe) id: number) { return this.products.findOne(id); }

Checklist: apakah Anda…

  • Menulis DTO sebagai class, bukan interface
  • Memakai decorator class-validator yang sesuai per field (@IsString, @MaxLength, @IsPositive)
  • Menandai field opsional dengan @IsOptional() dan memvalidasi isi array dengan { each: true }
  • Memasang ValidationPipe (global atau di route)
  • Memakai whitelist + forbidNonWhitelisted agar field asing ditolak
  • Mengubah id ke number dengan ParseIntPipe atau transform: true

Lulus jika minimal 4 dari 6.
