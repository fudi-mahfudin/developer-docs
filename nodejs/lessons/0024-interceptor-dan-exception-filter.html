Interceptor dan exception filter

Membungkus handler untuk logging, bentuk response, dan timeout; lalu mengubah exception menjadi format error yang konsisten

Dua komponen terakhir di pipeline bekerja di sisi keluar. Interceptor membungkus handler: ia jalan sebelum dan sesudahnya. Exception filter hanya bangun kalau ada exception yang lolos, lalu menentukan response error yang dikirim ke client.

Target lesson ini: Anda bisa menulis interceptor yang mencatat durasi request dan interceptor timeout, menjelaskan peran next.handle(), memilih built-in HttpException yang tepat (404, 409, 403, dll.), dan menulis exception filter yang membuat semua error berbentuk sama.

1. Interceptor: kode di sekitar handler

Interceptor bisa menambah logika sebelum atau sesudah method, mengubah hasil method, mengubah exception yang dilempar, atau mengganti method sepenuhnya (mis. untuk cache). [1] Class-nya mengimplementasikan NestInterceptor dengan method intercept(context, next). Argumen kedua adalah CallHandler; memanggil next.handle() berarti menjalankan handler. Kalau handle() tidak dipanggil, handler tidak dijalankan sama sekali. [1]

handle() mengembalikan Observable dari RxJS, library aliran data asinkron yang dipakai Nest. Untuk kebutuhan interview cukup anggap Observable sebagai "Promise yang bisa diproses dengan operator": tap() untuk efek samping tanpa mengubah nilai, map() untuk mengubah nilai, timeout() dan catchError() untuk batas waktu dan error. 

@Injectable()
export class LoggingInterceptor implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler): Observable<unknown> {
    const start = Date.now();                                   // sebelum handler
    return next.handle().pipe(
      tap(() => console.log(`selesai ${Date.now() - start}ms`)), // sesudah handler
    );
  }
}

@Injectable()
export class TimeoutInterceptor implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler) {
    return next.handle().pipe(
      timeout(5000),
      catchError(err => throwError(() =>
        err instanceof TimeoutError ? new RequestTimeoutException() : err)),
    );
  }
}

Dua catatan dari dokumentasi: callback tap() di atas tidak dipanggil kalau handler melempar exception, dan timeout hanya berhenti menunggu; pekerjaan yang sudah dimulai handler tidak ikut dibatalkan. [1] Interceptor transform yang membungkus hasil menjadi { data: ... } cukup memakai map(data => ({ data })). [1]

2. HttpException dan built-in exception

Nest punya exception layer bawaan. Exception yang bukan HttpException (mis. TypeError atau error dari driver database) menjadi { "statusCode": 500, "message": "Internal server error" }, sehingga detail internal tidak bocor. [2] Untuk error yang disengaja, lempar HttpException atau turunannya dari service atau controller: 

const order = await this.prisma.order.findUnique({ where: { id } });
if (!order) throw new NotFoundException(`Order ${id} tidak ditemukan`);   // 404

throw new ConflictException('Email sudah terdaftar');                     // 409
throw new HttpException('Kuota habis', HttpStatus.TOO_MANY_REQUESTS, { cause: err });

Konstruktor HttpException menerima body response, status, dan opsi; cause hanya untuk logging dan "is not serialized into the response object." Built-in exception yang paling sering dipakai: BadRequestException (400), UnauthorizedException (401), ForbiddenException (403), NotFoundException (404), ConflictException (409), UnprocessableEntityException (422), RequestTimeoutException (408), ServiceUnavailableException (503). [2]

NestJS ≥ 12: opsi HttpException menerima properti errorCode yang ikut dikirim di body response, berguna untuk kode error yang stabil bagi client. [3]

3. Exception filter: format error yang konsisten

Exception filter mengambil alih exception layer bawaan. Dekorator @Catch() menentukan tipe exception yang ditangani; @Catch() tanpa argumen menangkap semuanya. ArgumentsHost memberi akses ke request dan response, sama seperti di guard. [2] 

@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const res = ctx.getResponse<Response>();
    const req = ctx.getRequest<Request>();
    const status = exception instanceof HttpException ? exception.getStatus() : 500;
    const message = exception instanceof HttpException ? exception.getResponse() : 'Internal server error';
    res.status(status).json({ statusCode: status, message, path: req.url, timestamp: new Date().toISOString() });
  }
}

// app.module.ts
providers: [{ provide: APP_FILTER, useClass: AllExceptionsFilter }]

Daftarkan filter global lewat APP_FILTER kalau ia butuh DI (mis. logger). Satu jebakan: exception yang dilempar middleware hanya sampai ke filter global, tidak ke filter yang dipasang dengan @UseFilters(). [2] Kalau menggabungkan filter tangkap-semua dengan filter khusus tipe, deklarasikan filter tangkap-semua lebih dulu supaya filter khusus tetap menangani tipenya. [2]

Latihan lisan — Ucapkan dengan suara keras

Pasang timer dan jawab dengan suara keras, seolah sedang interview. Jangan buka jawaban contoh sebelum selesai.

"Tim frontend mengeluh bentuk error API kita berbeda-beda, dan sebagian endpoint lambat tanpa batas waktu. Apa yang Anda pasang di NestJS, dan bagaimana kerjanya?" (60 detik)
Bandingkan dengan jawaban contoh dan checklist-nya

"Untuk bentuk error, saya pasang satu exception filter global lewat APP_FILTER dengan @Catch() tanpa argumen supaya semua exception tertangkap. Filter itu memakai ArgumentsHost untuk mengambil response, membaca status dari HttpException atau memakai 500 untuk error lain, lalu mengirim JSON dengan bentuk yang sama: statusCode, message, path, timestamp. Di service, error yang disengaja saya lempar sebagai built-in exception seperti NotFoundException atau ConflictException, bukan Error biasa. Untuk batas waktu, saya pasang interceptor timeout: next.handle() mengembalikan Observable, saya tambahkan operator timeout lalu catchError yang mengubah TimeoutError menjadi RequestTimeoutException. Interceptor juga tempat logging durasi request dengan tap. Catatannya, timeout hanya berhenti menunggu, pekerjaan handler tidak ikut dibatalkan."

Checklist: apakah Anda menyebut…

  • Exception filter global (APP_FILTER atau useGlobalFilters) untuk format error
  • @Catch() tanpa argumen untuk menangkap semua exception, termasuk non-HTTP (500)
  • Built-in exception (NotFoundException, ConflictException) untuk error yang disengaja
  • Interceptor timeout dengan next.handle() + operator RxJS timeout
  • TimeoutError diubah menjadi RequestTimeoutException
  • Timeout tidak membatalkan pekerjaan yang sudah berjalan

Lulus jika minimal 4 dari 6.
