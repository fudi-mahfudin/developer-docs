Prisma dan PrismaService: satu client, di-inject seperti provider lain

schema.prisma, Prisma Client yang di-generate, pola PrismaService, select vs include, dan masalah N+1

Modul Pipeline request sudah membawa request sampai ke handler. Modul ini masuk ke langkah berikutnya: handler memanggil service, service membaca dan menulis database. Contoh di seluruh modul memakai Prisma, ORM (object-relational mapper: lapisan yang memetakan tabel database ke objek di kode) untuk Node.js dan TypeScript. Prisma tidak punya paket khusus Nest; integrasinya cukup satu provider bernama PrismaService. [1]

Target lesson ini: Anda bisa menulis di kertas PrismaService beserta satu method service yang memakainya, lalu menjelaskan dalam 60 detik beda select dan include dan cara menghindari query N+1.

Versi. Lesson ini memakai Prisma ORM 7, versi yang dipakai bab Prisma di dokumentasi NestJS. [1] Dokumentasi Prisma terbaru sudah membahas Prisma ORM 8, yang mengganti API client (mis. tidak ada lagi $transaction). [2] Kalau codebase Anda sudah di ORM 8, nama method-nya berbeda, tetapi konsep lesson ini (schema, client ber-type, provider yang di-inject, N+1) tetap sama.

1. schema.prisma dan Prisma Client

Semua bentuk data ditulis sekali di schema.prisma. Dari file ini, prisma generate menghasilkan Prisma Client: kode TypeScript ber-type untuk setiap model, jadi prisma.user.findMany() tahu kolom apa saja yang ada. Di Prisma ORM 7, generator-nya bernama prisma-client dan hasilnya ditulis ke folder di dalam proyek Anda. [1] 

generator client {
  provider = "prisma-client"
  output   = "../src/generated/prisma"
}

model User {
  id    Int    @id @default(autoincrement())
  email String @unique
  name  String?
  posts Post[]
}

model Post {
  id       Int    @id @default(autoincrement())
  title    String
  author   User   @relation(fields: [authorId], references: [id])
  authorId Int
}
schema.prisma→ prisma generate→ Prisma Client ber-type→ PrismaService (provider)

2. Pola PrismaService

Di Nest, client dibungkus sebagai provider: class yang extends PrismaClient, sehingga semua method client (this.user, this.$connect) langsung tersedia, dan class itu bisa di-inject ke service mana pun lewat constructor. Lifecycle hook menutup siklusnya: onModuleInit memanggil $connect(), onModuleDestroy memanggil $disconnect(). [1] Prisma ORM 7 juga mewajibkan driver adapter (paket yang menghubungkan client ke driver database, mis. @prisma/adapter-pg untuk PostgreSQL) saat membuat client. [3] 

import { Injectable, OnModuleDestroy, OnModuleInit } from '@nestjs/common';
import { PrismaPg } from '@prisma/adapter-pg';
import { PrismaClient } from '../generated/prisma/client';

@Injectable()
export class PrismaService extends PrismaClient implements OnModuleInit, OnModuleDestroy {
  constructor() {
    super({ adapter: new PrismaPg({ connectionString: process.env.DATABASE_URL }) });
  }
  async onModuleInit() { await this.$connect(); }
  async onModuleDestroy() { await this.$disconnect(); }
}

Daftarkan di satu module dan exports-kan, lalu module lain cukup meng-imports-nya. Karena provider default bersifat singleton, seluruh aplikasi berbagi satu PrismaService dan satu pool koneksi. Supaya onModuleDestroy juga jalan saat proses menerima SIGTERM, panggil app.enableShutdownHooks() di main.ts. [1] 

@Module({ providers: [PrismaService], exports: [PrismaService] })
export class PrismaModule {}

@Injectable()
export class UsersService {
  constructor(private readonly prisma: PrismaService) {}

  findByEmail(email: string) {
    return this.prisma.user.findUnique({ where: { email } });
  }
}

Kenapa tidak new PrismaClient() langsung di setiap service? Setiap instance membuka pool koneksi sendiri, dan service jadi sulit diuji karena tidak bisa diganti mock lewat DI.

3. select, include, dan N+1

Tanpa opsi, query Prisma mengembalikan semua kolom skalar model dan tidak menyertakan relasi. select dipakai kalau Anda hanya butuh beberapa field; include dipakai kalau Anda ingin record relasinya ikut terbawa. [4] Di API, select juga cara termudah agar kolom seperti passwordHash tidak pernah keluar di response. 

// hanya id dan email
await this.prisma.user.findMany({ select: { id: true, email: true } });

// user beserta post-nya
await this.prisma.user.findMany({ include: { posts: true } });

N+1 terjadi saat Anda melakukan loop atas hasil query lalu menjalankan satu query tambahan per hasil: 1 query untuk daftar user, N query untuk post tiap user. [5] 

// N+1: 1 query user + 1 query per user
const users = await this.prisma.user.findMany();
for (const u of users) {
  u.posts = await this.prisma.post.findMany({ where: { authorId: u.id } });
}

// perbaikan: biarkan Prisma mengambil relasinya sekaligus
const usersWithPosts = await this.prisma.user.findMany({ include: { posts: true } });

Dengan include, dokumentasi Prisma menyebut hasilnya hanya dua query SQL: satu untuk user, satu untuk post. [5] Alternatif lain: kumpulkan ID lalu pakai filter in (where: { authorId: { in: ids } }). Opsi relationLoadStrategy: "join" (fitur Preview di Prisma ORM 7) bahkan menggabungkannya menjadi satu query di database. [6]

Bandingkan dengan jawaban contoh dan checklist-nya 
@Injectable()
export class PrismaService extends PrismaClient implements OnModuleInit, OnModuleDestroy {
  constructor() {
    super({ adapter: new PrismaPg({ connectionString: process.env.DATABASE_URL }) });
  }
  async onModuleInit() { await this.$connect(); }
  async onModuleDestroy() { await this.$disconnect(); }
}

@Injectable()
export class PostsService {
  constructor(private readonly prisma: PrismaService) {}

  listWithAuthor() {
    return this.prisma.post.findMany({
      select: { id: true, title: true, author: { select: { name: true } } },
    });
  }
}

"PrismaService extends PrismaClient supaya bisa di-inject sebagai provider singleton, connect di onModuleInit. Relasi author diambil dalam query yang sama lewat nested select, jadi tidak ada loop query per post, dan hanya kolom name yang keluar."

Checklist: apakah Anda…

  • menulis PrismaService yang extends PrismaClient dengan @Injectable()?
  • memanggil $connect() di onModuleInit (dan idealnya $disconnect() di onModuleDestroy)?
  • meng-inject PrismaService lewat constructor service, bukan new PrismaClient()?
  • mengambil relasi author dalam satu panggilan (include atau nested select), bukan loop per post?
  • membatasi field user dengan select sehingga kolom lain (mis. hash password) tidak ikut?
  • menyebut bahwa PrismaService perlu didaftarkan dan di-exports dari sebuah module?
