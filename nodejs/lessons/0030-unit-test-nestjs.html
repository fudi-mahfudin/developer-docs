Unit test NestJS dengan Jest

Test.createTestingModule, mengganti provider dengan mock, dan menguji service yang memakai PrismaService tanpa database

Modul ini membahas apa yang membuat aplikasi NestJS siap dipakai sungguhan: test, konfigurasi, logging, shutdown, dan background job. Lesson pertama mulai dari yang paling sering diminta di live coding: "tulis unit test untuk service ini".

Target lesson ini: Anda bisa menulis di kertas, tanpa IDE, unit test Jest untuk service NestJS yang memakai PrismaService: menyusun testing module, mengganti PrismaService dengan mock jest.fn, dan menguji jalur sukses serta jalur error.

1. Jest di proyek NestJS

Jest adalah test runner yang dipakai proyek NestJS CommonJS: ia menemukan file *.spec.ts, menjalankan blok describe/it, dan menyediakan expect serta mock function. Paket @nestjs/testing sendiri agnostik terhadap test runner. [1]

Label versi NestJS 12: proyek ESM baru dibuat dengan Vitest sebagai default, sementara proyek CommonJS tetap memakai Jest, dan API @nestjs/testing sama untuk keduanya. Paket inti NestJS 12 dikirim sebagai ESM, sehingga Jest baru bisa memuatnya di Node ≥ 24.9. [2] Contoh di track ini memakai Jest.

2. Test.createTestingModule: DI container kecil untuk test

Test.createTestingModule() menerima metadata yang sama dengan @Module() (providers, imports, controllers) dan mengembalikan builder. compile() bersifat asinkron dan menghasilkan TestingModule, jadi harus di-await. Provider biasa diambil dengan moduleRef.get(); provider ber-scope REQUEST atau TRANSIENT diambil dengan resolve(). [1]

createTestingModule({ providers })→ overrideProvider(...).useValue(mock)→ await compile()→ moduleRef.get(UsersService)→ panggil method + expect

Kenapa tidak new UsersService(prismaMock) saja? Bisa, dan untuk service kecil itu sah. Testing module berguna kalau service punya beberapa dependency, memakai injection token, atau Anda ingin memastikan wiring DI-nya benar.

Ada dua cara mengganti dependency dengan mock:

  • Daftarkan sendiri: providers: [UsersService, { provide: PrismaService, useValue: prismaMock }]. Paling umum untuk unit test satu service.
  • Override: kalau test meng-import module utuh (imports: [UsersModule]), pakai .overrideProvider(PrismaService).useValue(prismaMock) sebelum compile(). Selain useValue, tersedia useClass dan useFactory. [1]

3. Mock PrismaService dengan jest.fn

jest.fn() membuat mock function: fungsi palsu yang mencatat setiap panggilan dan argumennya, dan mengembalikan undefined kalau tidak diberi implementasi. Untuk method async seperti query Prisma, pakai mockResolvedValue(value), singkatan dari mockImplementation(() => Promise.resolve(value)). Untuk jalur error, mockRejectedValue(err). [3]

Mock cukup berisi method yang benar-benar dipanggil service. Objek kecil yang ditulis tangan lebih mudah dibaca di interview daripada mock seluruh PrismaClient. Dokumentasi Prisma juga menunjukkan mockDeep<PrismaClient>() dari jest-mock-extended kalau Anda butuh mock yang lengkap dan bertipe. [4] 

// users.service.ts
@Injectable()
export class UsersService {
  constructor(private readonly prisma: PrismaService) {}

  async findOne(id: number) {
    const user = await this.prisma.user.findUnique({ where: { id } });
    if (!user) throw new NotFoundException(`User ${id} tidak ada`);
    return user;
  }
}
// users.service.spec.ts
describe('UsersService', () => {
  let service: UsersService;
  const prisma = { user: { findUnique: jest.fn() } };

  beforeEach(async () => {
    const moduleRef = await Test.createTestingModule({
      providers: [UsersService, { provide: PrismaService, useValue: prisma }],
    }).compile();
    service = moduleRef.get(UsersService);
    jest.clearAllMocks();
  });

  it('melempar NotFoundException kalau user tidak ada', async () => {
    prisma.user.findUnique.mockResolvedValue(null);
    await expect(service.findOne(2)).rejects.toThrow(NotFoundException);
    expect(prisma.user.findUnique).toHaveBeenCalledWith({ where: { id: 2 } });
  });
});

Tiga hal yang dinilai interviewer di kode ini:

  • Arrange, act, assert: atur nilai mock, panggil method, periksa hasil. Satu perilaku per it.
  • Jalur error ikut diuji: await expect(promise).rejects.toThrow(...). Lupa await di sini membuat test lulus tanpa benar-benar memeriksa apa pun.
  • Mock di-reset antar test: mockClear() mengosongkan catatan panggilan tapi mempertahankan implementasi; mockReset() juga membuang implementasinya. [3] Tanpa reset, toHaveBeenCalledWith bisa lulus karena panggilan dari test sebelumnya.

Yang tidak dibuktikan unit test ini: query Prisma-nya benar terhadap database sungguhan. Itu tugas integration atau e2e test (lesson 0031).

Bandingkan dengan jawaban contoh dan checklist-nya 
describe('UsersService', () => {
  let service: UsersService;
  const prisma = { user: { findUnique: jest.fn() } };
  beforeEach(async () => {
    const moduleRef = await Test.createTestingModule({
      providers: [UsersService, { provide: PrismaService, useValue: prisma }],
    }).compile();
    service = moduleRef.get(UsersService);
    jest.clearAllMocks();
  });
  it('mengembalikan user kalau ada', async () => {
    prisma.user.findUnique.mockResolvedValue({ id: 1, email: 'a@b.c' });
    await expect(service.findOne(1)).resolves.toEqual({ id: 1, email: 'a@b.c' });
    expect(prisma.user.findUnique).toHaveBeenCalledWith({ where: { id: 1 } });
  });
  it('melempar NotFoundException kalau tidak ada', async () => {
    prisma.user.findUnique.mockResolvedValue(null);
    await expect(service.findOne(2)).rejects.toThrow(NotFoundException);
  });
});

Checklist: apakah kode Anda…

  • memakai Test.createTestingModule dengan UsersService di providers, lalu await compile()?
  • mengganti PrismaService dengan { provide: PrismaService, useValue: mock } atau overrideProvider?
  • membuat mock yang hanya berisi method yang dipakai: user.findUnique = jest.fn()?
  • memakai mockResolvedValue untuk hasil async (data dan null)?
  • menguji dua kasus: ditemukan, dan null → rejects.toThrow(NotFoundException)?
  • memeriksa argumen dengan toHaveBeenCalledWith dan mereset mock antar test?

Lulus jika minimal 4 dari 6.
