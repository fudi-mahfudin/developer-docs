E2E test dengan supertest

Menyalakan aplikasi NestJS utuh di dalam test, mengirim request HTTP sungguhan, dan memilih database untuk test

Di lesson 0030, unit test membuktikan logika service dengan PrismaService palsu. Yang belum terbukti: route, guard, pipe, dan query ke database bekerja bersama. Itu tugas e2e test.

Target lesson ini: Anda bisa menulis kerangka e2e test NestJS dengan supertest (createNestApplication, app.init(), app.close()), menyebut jebakan konfigurasi main.ts, dan menjelaskan dalam 60 detik pembagian unit, integration, dan e2e test serta database yang dipakai.

1. Unit vs integration vs e2e

JenisYang diujiDependencyMenangkap
UnitSatu class (service, guard, pipe)Di-mockLogika cabang, error yang dilempar
IntegrationBeberapa komponen sungguhanSebagian nyata, mis. service + database testQuery salah, mapping data, transaksi
E2EAplikasi utuh lewat HTTPNyata, kecuali layanan eksternalRoute, status code, validasi, guard, format response

Porsinya: banyak unit test (cepat, murah), sedikit e2e untuk alur kritis (login, checkout). E2E lebih lambat dan lebih sulit didiagnosis saat gagal, jadi tidak dipakai untuk setiap cabang logika.

2. Kerangka e2e test

compile() saja tidak membuat HTTP adapter. Untuk e2e, buat aplikasi dengan moduleRef.createNestApplication(), jalankan await app.init(), lalu berikan app.getHttpServer() ke supertest. Tutup dengan await app.close() di afterAll. Konvensi Nest: file e2e di folder test dengan akhiran .e2e-spec. [1]

supertest adalah library untuk menguji server HTTP: ia menerima http.Server atau fungsi handler, dan kalau server belum listen, ia mengikatnya ke port ephemeral sendiri. Jadi app.listen() tidak perlu. Request mengembalikan Promise, sehingga bisa di-await. [2] 

// test/users.e2e-spec.ts
describe('Users (e2e)', () => {
  let app: INestApplication;
  beforeAll(async () => {
    const moduleRef = await Test.createTestingModule({ imports: [AppModule] }).compile();
    app = moduleRef.createNestApplication();
    app.useGlobalPipes(new ValidationPipe({ whitelist: true })); // sama dengan main.ts
    await app.init();
  });

  afterAll(async () => { await app.close(); });

  it('POST /users menolak email tidak valid', () =>
    request(app.getHttpServer()).post('/users').send({ email: 'bukan-email' }).expect(400));

  it('GET /users/1 mengembalikan JSON', async () => {
    const res = await request(app.getHttpServer()).get('/users/1').expect(200);
    expect(res.body).toMatchObject({ id: 1 });
  });
});

Jebakan klasik: test membuat aplikasi dari TestingModule, bukan dari main.ts. Global pipe, filter, prefix, atau CORS yang dipasang di bootstrap tidak ikut. Pasang ulang di test (seperti baris useGlobalPipes di atas), atau daftarkan lewat provider APP_PIPE/APP_FILTER di module supaya otomatis terbawa.

app.close() menjalankan hook shutdown, misalnya PrismaService memutus koneksi. Tanpa itu, koneksi yang masih terbuka membuat Jest menggantung atau memperingatkan open handles.

Layanan eksternal (payment gateway, email) tetap diganti dengan .overrideProvider(...) di e2e, supaya test tidak mengirim email sungguhan. [1]

3. Database untuk test

Panduan integration testing Prisma menjalankan test terhadap database di lingkungan test tersendiri, yaitu Postgres lewat Docker Compose, terpisah dari database production dan development. Data diisi di beforeAll dan dihapus sesudahnya dengan deleteMany() di dalam $transaction; TRUNCATE lewat raw SQL disebut sebagai opsi yang lebih efisien untuk banyak tabel. [3]

Jalankan Postgres test (Docker)→ DATABASE_URL ke DB test→ prisma migrate deploy→ seed di beforeAll→ jalankan e2e→ bersihkan data + app.close()

Tiga aturan yang sering ditanyakan:

  • Jangan pernah ke production atau database development orang lain. Test menghapus data.
  • Test tidak saling bergantung. Setiap test (atau suite) menyiapkan datanya sendiri, sehingga urutan eksekusi tidak mengubah hasil.
  • Engine yang sama dengan production. Mengganti Postgres dengan database lain hanya untuk test bisa meloloskan perbedaan perilaku SQL.

"Bagaimana Anda membagi test di aplikasi NestJS: apa yang diuji unit test, integration test, dan e2e test, dan bagaimana menangani database?" (60 detik)
Bandingkan dengan jawaban contoh dan checklist-nya

"Unit test menguji satu class, biasanya service, dengan dependency di-mock lewat Test.createTestingModule dan useValue. Cepat dan banyak, tapi tidak membuktikan query benar. Integration test memasang beberapa bagian sungguhan, misalnya service dengan PrismaService ke database test. E2E test menyalakan aplikasi utuh dengan createNestApplication dan app.init, lalu mengirim request HTTP lewat supertest ke app.getHttpServer, dan memeriksa status serta body. Database-nya database khusus test, misalnya Postgres di Docker, dengan migrasi dijalankan dulu dan data dibersihkan antar suite supaya test tidak saling bergantung. Global pipe dan konfigurasi dari main.ts dipasang ulang di test, dan app.close di afterAll. Porsinya: banyak unit test, sedikit e2e untuk alur kritis."

Checklist: apakah Anda menyebut…

  • unit test: satu class, dependency di-mock, cepat, tidak membuktikan query?
  • integration test: beberapa komponen sungguhan, misalnya ke database test?
  • e2e: createNestApplication + app.init(), request via supertest ke getHttpServer()?
  • database khusus test (bukan production/dev), migrasi dulu, data dibersihkan?
  • konfigurasi main.ts (global pipe) dipasang ulang di test, app.close() di afterAll?
  • porsi: banyak unit, sedikit e2e untuk alur kritis?

Lulus jika minimal 4 dari 6.
