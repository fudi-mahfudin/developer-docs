Background job dengan BullMQ

Kenapa pekerjaan dipindah ke luar request, producer dan processor di @nestjs/bullmq, retry + backoff, dan idempotency

Beberapa pekerjaan tidak cocok dikerjakan di dalam request: mengirim email, membuat PDF, memanggil API pihak ketiga yang lambat. Lesson terakhir modul ini memindahkannya ke queue.

Target lesson ini: Anda bisa menulis di kertas registrasi queue, producer, dan processor @nestjs/bullmq dengan retry dan backoff exponential, dan menjelaskan kenapa handler job harus idempoten.

1. Kenapa job dipindah ke luar request

Queue adalah daftar pekerjaan yang disimpan di luar proses: producer menaruh job, worker mengambil dan mengerjakannya nanti, terpisah dari siklus request. Request yang menunggu pekerjaan 40 detik menahan koneksi, rawan timeout di proxy, dan pekerjaannya hilang kalau proses restart. Dengan queue, handler hanya menambah job lalu menjawab (misalnya 202 Accepted dengan id job), dan job yang gagal bisa diulang.

POST /reports→ Producer: queue.add()→ Redis (job tersimpan)→ Worker: process(job)→ completed, atau retry → failed

BullMQ adalah library queue untuk Node yang secara default menyimpan job di Redis; @nestjs/bullmq membungkusnya dengan module dan decorator NestJS. Install: npm install @nestjs/bullmq bullmq ioredis. [1] Worker bisa berjalan di proses yang sama dengan API, atau di proses/container terpisah supaya pekerjaan berat tidak memblokir event loop API.

2. Producer dan processor di @nestjs/bullmq

Koneksi Redis didaftarkan sekali dengan BullModule.forRoot({ connection: { host, port } }), lalu setiap queue dengan BullModule.registerQueue({ name }). Producer meng-inject queue dengan @InjectQueue('nama') dan memanggil queue.add(namaJob, data, opts). Consumer adalah class @Processor('nama') yang extends WorkerHost dan mengimplementasikan async process(job); event worker ditangkap dengan @OnWorkerEvent('completed') dan sejenisnya. [1] 

// app.module.ts
BullModule.forRoot({ connection: { host: 'localhost', port: 6379 } }),
BullModule.registerQueue({ name: 'email' }),

// users.service.ts (producer)
constructor(@InjectQueue('email') private emailQueue: Queue) {}

await this.emailQueue.add('welcome', { userId: user.id }, {
  attempts: 5,
  backoff: { type: 'exponential', delay: 1000 },
  jobId: `welcome-${user.id}`,
});

// email.processor.ts (consumer)
@Processor('email')
export class EmailProcessor extends WorkerHost {
  async process(job: Job<{ userId: number }>) {
    if (job.name === 'welcome') await this.sendWelcome(job.data.userId);
  }
}

Data job sebaiknya kecil dan bisa diserialisasi ke JSON, misalnya userId, bukan seluruh objek user. Worker membaca data terbaru dari database saat job dijalankan.

3. Retry dan backoff

Job yang melempar error dianggap gagal. Tanpa attempts lebih dari 1, job yang gagal tidak diulang. attempts adalah jumlah percobaan maksimum, dan backoff mengatur jeda: fixed (jeda tetap) atau exponential, dengan jeda 2^(attempts - 1) × delay milidetik. Opsi jitter (0–1) mengacak jeda supaya banyak job yang gagal bersamaan tidak mengulang di detik yang sama. [2]

Percobaan ulang ke-Jeda (exponential, delay 1000)
11 detik
22 detik
34 detik
48 detik

Setelah percobaan habis, job pindah ke status failed, dan bisa disimpan untuk diperiksa atau dihapus otomatis sesuai pengaturan queue. [2] Backoff exponential memberi waktu bagi dependency yang sedang bermasalah untuk pulih, alih-alih dibanjiri percobaan ulang.

4. Idempotency secara singkat

Idempotent berarti menjalankan operasi dua kali berefek sama dengan menjalankannya sekali. Retry membuat handler job bisa berjalan lebih dari sekali: kalau job gagal setelah email terkirim tapi sebelum statusnya disimpan, percobaan ulang mengirim email kedua. Karena itu handler memeriksa penanda sebelum melakukan efek samping: 

async sendWelcome(userId: number) {
  const user = await this.prisma.user.findUniqueOrThrow({ where: { id: userId } });
  if (user.welcomeSentAt) return;                       // sudah pernah: lewati
  await this.mailer.send(user.email, 'Selamat datang');
  await this.prisma.user.update({ where: { id: userId }, data: { welcomeSentAt: new Date() } });
}

Di sisi producer, jobId custom mencegah job ganda: menambah job dengan id yang sudah ada diabaikan dan tidak masuk queue. Id custom tidak boleh mengandung : dan tidak boleh hanya angka, jadi pakai prefix seperti welcome-42. Job yang sudah dihapus tidak dihitung sebagai duplikat. [3]

Latihan 2 — Retry dan idempotency

Latihan lisan — Tulis kode di kertas

Pasang timer 5 menit dan tulis jawabannya di kertas, tanpa IDE, seolah sedang live coding. Jangan buka jawaban contoh sebelum selesai. Soal ini juga ada di bank soal dan bisa ditarik review 0035.

Setelah user mendaftar, UsersService menambah job welcome ke queue email dengan retry 5 kali dan backoff exponential, dan processor-nya mengirim email. Tulis registrasi queue, producer, dan processor.
Bandingkan dengan jawaban contoh dan checklist-nya 
// users.module.ts
@Module({ imports: [BullModule.registerQueue({ name: 'email' })], providers: [UsersService, EmailProcessor] })
export class UsersModule {}

// users.service.ts
constructor(@InjectQueue('email') private emailQueue: Queue, private prisma: PrismaService) {}

async register(dto: RegisterDto) {
  const user = await this.prisma.user.create({ data: dto });
  await this.emailQueue.add('welcome', { userId: user.id }, {
    jobId: `welcome-${user.id}`,
    attempts: 5,
    backoff: { type: 'exponential', delay: 1000 },
  });
  return user;
}

// email.processor.ts
@Processor('email')
export class EmailProcessor extends WorkerHost {
  async process(job: Job<{ userId: number }>) {
    const user = await this.prisma.user.findUniqueOrThrow({ where: { id: job.data.userId } });
    if (user.welcomeSentAt) return;           // idempoten
    await this.mailer.send(user.email, 'Selamat datang');
    await this.prisma.user.update({ where: { id: user.id }, data: { welcomeSentAt: new Date() } });
  }
}

Checklist: apakah kode Anda…

  • mendaftarkan BullModule.registerQueue({ name: 'email' }) (dan BullModule.forRoot dengan koneksi Redis)?
  • meng-inject @InjectQueue('email') di producer dan memanggil queue.add(nama, data, opts)?
  • mengirim data job kecil (userId), bukan seluruh objek user?
  • memberi opts attempts: 5 dan backoff { type: 'exponential', delay }?
  • menulis @Processor('email') class extends WorkerHost dengan async process(job)?
  • membuat handler idempoten (cek welcomeSentAt atau jobId unik) karena retry bisa mengulang?
