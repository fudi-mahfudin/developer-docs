Pipeline request NestJS

Ringkasan satu halaman untuk dibaca ulang menjelang interview. Dari Lesson 0021 (urutan dan binding), 0022 (pipe), 0023 (guard dan middleware), dan 0024 (interceptor dan filter). Latihan penuhnya: mock 0036.

Urutan eksekusi satu request

Middleware→ Guard→ Interceptor (sebelum)→ Pipe→ Handler→ Interceptor (sesudah)→ Exception filter

Dokumentasi Nest: "a request flows through middleware, then guards, then interceptors, then pipes, and finally back through interceptors on the return path." [1] Exception filter hanya bekerja kalau ada exception yang tidak ditangkap di langkah mana pun. Guard jalan "after all middleware, but before any interceptor or pipe." [2]

Kebutuhan → pakai yang mana

KebutuhanPakaiAlasan singkat
Logging akses, correlation id, CORS, body parserMiddlewareBerlaku untuk setiap request mentah; tidak perlu tahu handler
Autentikasi (token valid?)GuardMenolak sebelum ada kerja lain; lempar UnauthorizedException (401)
Otorisasi role (hanya admin, dsb.)Guard@Roles('admin') dibaca guard: punya ExecutionContext, membaca metadata handler lewat Reflector; false → ForbiddenException (403)
Validasi body/DTOPipeValidationPipe + class-validator; whitelist membuang properti asing, forbidNonWhitelisted menolaknya (400)
Ubah tipe parameter ("42" → 42)PipeParseIntPipe, ParseUUIDPipe per parameter
Bentuk response seragam ({ data: … })InterceptorMembungkus handler; memetakan hasil dengan operator RxJS setelah next.handle()
Durasi request, timeout, cache responseInterceptorPunya bagian sebelum dan sesudah handler
Format error yang konsistenException filterMengubah exception yang lolos menjadi response error

Kenapa otorisasi di guard, bukan middleware: middleware tidak tahu handler mana yang akan dipanggil setelah next(), sedangkan guard tahu. [2] Akibat urutan: user tanpa role yang mengirim body tidak valid mendapat 403, bukan 400.

Urutan di dalam satu jenis komponen

  • Guard, interceptor (sebelum), pipe: global → controller → method; pipe parameter paling akhir.
  • Interceptor (sesudah): terbalik, method → controller → global, "in a first-in, last-out manner." [1]
  • Exception filter: dari level terendah: method → controller → global. Exception yang Anda tangkap sendiri dengan try/catch tidak sampai ke filter.
