Urutan event loop

Ringkasan satu halaman untuk dibaca ulang menjelang interview. Dari Lesson 0002 (fase) dan 0003 (nextTick dan microtask). Latihan penuhnya: mock 0036.

Enam fase dalam satu putaran

timers→ pending callbacks→ idle, prepare→ poll→ check→ close callbacks↻
FaseCallback yang dijalankan
timerssetTimeout() dan setInterval() yang waktunya sudah lewat
pending callbacksCallback I/O yang ditunda ke putaran berikutnya (mis. beberapa error TCP)
idle, prepareInternal
pollCallback I/O; Node menunggu di sini kalau tidak ada pekerjaan lain
checksetImmediate()
close callbacksEvent close, mis. socket.on('close', …)

Fase dan isinya mengikuti panduan resmi Node. [1]

Prioritas: nextTick → microtask → fase berikutnya

Kode sinkron / satu callback→ next tick queue→ microtask queue→ callback / fase berikutnya
  • Setelah kode sinkron atau setiap callback selesai, Node mengosongkan seluruh next tick queue (process.nextTick), lalu seluruh microtask queue (Promise.then, lanjutan await, queueMicrotask). [2]
  • nextTick yang dijadwalkan dari dalam microtask menunggu sampai microtask queue habis, lalu jalan sebelum loop lanjut.
  • Pengecualian ESM: di top-level modul ESM, microtask (then, queueMicrotask) jalan sebelum nextTick, karena modul ESM sendiri dijalankan sebagai bagian dari microtask queue. [2] Semua soal di bawah memakai CommonJS.
  • nextTick rekursif bisa membuat I/O kelaparan (starvation), karena loop tidak pernah sampai ke poll.

setTimeout(fn, 0) vs setImmediate(fn)

Dipanggil dariUrutan
Main module (top-level file)tidak deterministik: bergantung apakah 1 ms sudah lewat saat loop masuk fase timers
Di dalam callback I/OSelalu setImmediate duluan: callback I/O di poll, fase berikutnya check

Keduanya dari panduan resmi Node. [1] Delay di bawah 1 diubah menjadi 1 ms. [3]

Soal tebak urutan output

Tulis urutannya di kertas dulu, baru buka jawaban. Semua kunci diverifikasi dengan menjalankan kodenya di Node 24 (CommonJS).

Soal 1 — di dalam callback I/O

const fs = require('node:fs');
fs.readFile(__filename, () => {
  setTimeout(() => console.log('timeout'), 0);
  setImmediate(() => console.log('immediate'));
});
Lihat jawaban soal 1
  1. immediate
  2. timeout

Callback readFile berjalan di poll; fase berikutnya check, jadi immediate duluan. Timer menunggu fase timers putaran berikutnya.

Soal 2 — async/await

async function f() {
  console.log('f mulai');
  await g();
  console.log('f selesai');
}
async function g() {
  console.log('g');
}
console.log('awal');
f();
Promise.resolve().then(() => console.log('then'));
console.log('akhir');
Lihat jawaban soal 2
  1. awal
  2. f mulai
  3. g
  4. akhir
  5. f selesai
  6. then

Badan async function jalan sinkron sampai await pertama, termasuk isi g(). Lanjutan setelah await masuk microtask queue lebih dulu daripada then, jadi "f selesai" mendahului "then".

Soal 3 — microtask di antara dua timer

setTimeout(() => {
  console.log('t1');
  Promise.resolve().then(() => console.log('promise dari t1'));
  process.nextTick(() => console.log('tick dari t1'));
}, 0);
setTimeout(() => console.log('t2'), 0);
Lihat jawaban soal 3
  1. t1
  2. tick dari t1
  3. promise dari t1
  4. t2

Kedua antrean dikosongkan setelah setiap callback, bukan setelah seluruh fase timers selesai. Jadi nextTick lalu promise dari t1 jalan sebelum t2.

Soal 4 — executor, then berantai, queueMicrotask

const p = new Promise(resolve => {
  console.log('executor');
  resolve();
});
p.then(() => console.log('then 1')).then(() => console.log('then 2'));
queueMicrotask(() => console.log('microtask'));
process.nextTick(() => console.log('nextTick'));
console.log('sync');
Lihat jawaban soal 4
  1. executor
  2. sync
  3. nextTick
  4. then 1
  5. microtask
  6. then 2

Executor Promise jalan sinkron. Setelah kode sinkron: nextTick dulu, lalu microtask sesuai urutan masuk: then 1, microtask. "then 2" baru masuk antrean setelah then 1 selesai, jadi paling akhir.
