Stored Procedure, function, dan memanggil SP dari .NET

Ringkasan satu halaman. Dari Lesson 0020. Skrip lab: lab/0020-stored-procedure.sql.

Kerangka SP [1] [3]

CREATE OR ALTER PROCEDURE dbo.usp_AdjustStock      -- usp_, bukan sp_ (system procedure)
    @ProductId int,
    @Delta     int,
    @NewStock  int = NULL OUTPUT                   -- default boleh konstanta atau NULL
AS
BEGIN
    SET NOCOUNT ON;
    SET XACT_ABORT ON;
    BEGIN TRY
        BEGIN TRANSACTION;
        IF NOT EXISTS (SELECT 1 FROM dbo.Product WHERE Id = @ProductId)
            THROW 50001, N'Product tidak ditemukan.', 1;
        UPDATE dbo.Product SET Stock = Stock + @Delta
        WHERE Id = @ProductId AND Stock + @Delta >= 0;
        IF @@ROWCOUNT = 0
            THROW 50002, N'Stock tidak boleh negatif.', 1;
        SELECT @NewStock = Stock FROM dbo.Product WHERE Id = @ProductId;
        COMMIT TRANSACTION;
    END TRY
    BEGIN CATCH
        IF @@TRANCOUNT > 0 ROLLBACK TRANSACTION;
        THROW;                                      -- wajib: error di CATCH tidak sampai ke aplikasi
    END CATCH
END;
GO
DECLARE @s int, @status int;
EXEC @status = dbo.usp_AdjustStock @ProductId = 1, @Delta = -5, @NewStock = @s OUTPUT;  -- OUTPUT di EXEC juga
  • Mengembalikan: result set (SELECT, 0..n), parameter OUTPUT, RETURN (int status saja).
  • Lupa OUTPUT di EXEC → tidak error, nilainya tidak kembali.
  • THROW: nomor ≥ 50000, tidak perlu di sys.messages, severity 16, menghormati XACT_ABORT; statement sebelumnya wajib diakhiri ;. Kode baru pakai THROW, bukan RAISERROR. [4]
  • TRY...CATCH menangkap error severity > 10 yang tidak memutus koneksi; tidak menangkap compile error di level yang sama. [2]
  • Best practice: SET NOCOUNT ON, nama schema, tanpa SELECT *, transaction sependek mungkin, jangan bungkus kolom dengan fungsi di WHERE (lesson 0023).

  • FromSql: hanya di DbSet, hasil harus memuat semua kolom entity, SP tidak bisa di-compose. ExecuteSql: tanpa result set, mengembalikan jumlah baris. SqlQuery<T>: scalar/DTO.
  • SP pun rentan injection bila menggabungkan string ke EXEC (@sql) → sp_executesql dengan parameter. [9]
  • Node: Dapper ≈ pg/mssql; FromSql ≈ Prisma $queryRaw; FromSqlRaw ≈ $queryRawUnsafe.

Jawaban 60–90 detik

Default EF Core/LINQ untuk CRUD: logika di C#, bisa di-unit-test, ikut versioning aplikasi, tetap berparameter dan plan-nya di-cache. SP untuk operasi set-based berat, query yang sulit di LINQ, atau bila akses harus lewat izin EXECUTE. SP tidak otomatis lebih cepat (plan dipakai ulang → parameter sniffing), dan biayanya testability serta deploy terpisah. Panggil dengan FromSql/ExecuteSql atau Dapper CommandType.StoredProcedure; jangan pernah FromSqlRaw dengan $"...".
