Latency, throughput, percentile

  • Latency = waktu satu request (ms). Throughput = request per detik (QPS). Menambah server menaikkan throughput, tidak mempercepat satu request yang lambat.
  • Latency adalah distribusi: tulis target sebagai percentile, mis. p99 < 300 ms, bukan rata-rata. Rata-rata menyembunyikan ekor. [2]
  • Fan-out memperbesar ekor: halaman yang memanggil 100 service, masing-masing 1% lambat, kena minimal satu panggilan lambat dengan peluang 1 − 0,99100 ≈ 63%.

Empat rumus

DAU × request/user/hari→ ÷ 10⁵ = QPS rata-rata→ × faktor puncak = QPS puncak→ × ukuran = bandwidth / storage
  • QPS = DAU × request per user per hari / 10⁵. DAU = user yang aktif minimal sekali sehari, bukan akun terdaftar.
  • QPS puncak = QPS rata-rata × faktor puncak (asumsi, sering 2–3×). Kalau 30% request datang dalam satu jam: 0,3 × total / 3.600.
  • Storage = record baru per hari × ukuran × 365 × tahun disimpan (+ index dan replika).
  • Bandwidth = QPS × ukuran request/response. Hitung baca dan tulis terpisah.
